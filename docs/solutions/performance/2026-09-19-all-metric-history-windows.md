# 모든 건강 지표의 과거 탐색과 제한된 구간 조회

## Problem

체중 외 15개 지표의 차트는 기간 버퍼까지만 이동할 수 있었다. 전체 데이터 목록의 8개 지표는 과거 페이지를 읽을 때 현재까지 누적 조회해 최근 기록을 반복 추가했다. 빈 30일 구간을 이력의 끝으로 간주하여 수년 전 기록도 누락했다. 공유 스냅샷은 캐시 무효화 이전에 시작한 조회가 새 캐시를 덮어쓸 수 있었다.

## Solution

- `MetricHistoryQueryService`는 지표별 최초 기록과 지정 날짜 이전의 마지막 기록을 limit-one 쿼리로 읽는다. HealthKit의 16개 샘플 타입을 명시적으로 매핑한다.
- `AllDataViewModel`은 모든 지표에 고정된 달력 날짜 기준 `[start, end)` 페이지를 사용한다. 빈 구간에서는 이전 실제 기록 날짜로 건너뛴다. 체중 전용 전체 배열/200개 페이지 분기를 제거했다.
- HRV·호흡장애에 날짜 구간 API를 추가하고, 다른 지표도 기존 구간 API를 사용한다. 목록의 안정시 심박·걸음은 일별 통계 쿼리를 사용한다. 수면 목록은 실제 취침 시각을 보존한다.
- `MetricDetailViewModel`의 전체 스크롤 범위는 최초 기록까지 열어 두되, 실제 데이터는 선택 기간의 주변 구간만 읽는다. 빈 과거 구간에서도 차트 표면을 유지한다. 체중도 같은 조회 정책을 사용한다.
- 초기 조회 기준일을 고정해 스크롤 도중 `Date()` 변화로 불필요한 재조회가 발생하지 않게 한다. 명시적 기간 전환은 이전 loaded range를 무효화해 스크롤 prefetch가 초기 조회를 덮어쓰지 못하게 한다.
- 기존 chartData는 조회 중 유지하고, 요청 ID·취소 검사 후 교체한다. 현재 요약 통계는 과거 조회 중 보존한다. 별도의 Today 점수/최근 기간 정책은 변경하지 않는다.
- 후속 연속 스크롤 수정에서는 prefetch를 요약 debounce와 분리하고 5개 화면 구간을 미리 읽는다. 실행 중인 조회를 유지한 뒤 최신 위치로 따라잡으며, 체중 Y축은 과거 탐색 중 축소하지 않는다. [원인과 회귀 검증](2026-09-19-chart-prefetch-scroll-starvation.md)을 참조한다.
- AreaLine·DotLine·RangeBar·Bar 차트는 제한된 날짜 눈금을 사용한다. DotLine의 Y축 캐시는 점 개수가 아니라 데이터 내용 변경에 반응한다. 체중 Y축은 스크롤마다 전체 배열을 순회하지 않고 데이터 교체 시 계산한다.
- 수면 일별 합계는 한 번의 HealthKit 구간 조회 후 날짜별 샘플 슬라이스를 처리한다. 기존 Watch 우선 중복 제거, non-Watch gap 보존, 정오 기준과 늦은 기상 연속성 규칙을 재사용하며 CPU 처리는 취소 가능한 detached task에서 수행한다.
- 공유 스냅샷의 세대 번호를 비교하여 무효화 이전 요청의 캐시 저장·실행 중 요청 해제를 차단한다.

## Validation

- 실기기 대상 빌드 및 커밋 훅 빌드 통과.
- 관련 6개 suite의 단위 테스트 83개 통과. 최종 기간 전환 수정 후 관련 2개 suite 26개 재검증 통과.
- 16개 지표 공통 매개변수 테스트: 2011년 기록, 빈 연도 통과, 페이지 중복 방지, 종료 조건, 과거 차트의 제한된 데이터 개수, 현재 요약 보존.
- 별도 회귀 테스트: 무효화된 캐시 요청의 늦은 완료, 기간 변경 중 보류된 쿼리와 prefetch 경합, 최근 구간 재조회 방지, DST 경계 수면 날짜.
- iPhone 17 / iOS 27.0 UI: HRV·안정시 심박·수면·걸음·체중 장기 스크롤 5개와 제스처 시나리오를 확인했다. 최초 10개 실행에서 8개 통과, 2개는 최신 날짜에서 미래 방향으로 드래그하던 기존 테스트 오류였다. 과거 방향으로 수정하고 선택 후 실제 날짜 이동 assertion도 추가했다. 관련 3개 재실행은 실패 0으로 통과하여 최종 10개 시나리오를 모두 검증했다.
- 첫 UI 실행은 테스트 종료 후 Xcode 결과 수집이 지연되어 종료했다. 개별 테스트 결과는 로그에서 확인했으며, 최종 3개 재실행은 `TEST SUCCEEDED`로 정상 종료했다.

## Prevention

1. 빈 날짜 구간을 전체 이력의 종료 조건으로 사용하지 않는다.
2. 페이지 기준일과 반개구간 경계를 고정한다. 통계 버킷에도 같은 경계를 적용한다.
3. 탐색 도메인과 조회·렌더링 데이터 범위를 분리한다. `.distantPast`를 고밀도 지표 전체 조회에 사용하지 않는다.
4. 장기 수면 조회에서 날짜 수만큼 HealthKit 쿼리를 동시에 시작하지 않는다.
5. 같은 점 개수의 값 교체, 기간 변경 중 스크롤, 무효화 중 완료 순서 역전을 검증한다.

## Lessons Learned

모든 지표의 사용자 경험은 통일하되 집계 의미는 유지해야 한다. 걸음·운동은 합계, 안정시 심박은 범위/평균, 수면은 중복 제거한 일별 수면량을 사용한다. 새 과거 구간의 첫 조회에는 비동기 지연이 있을 수 있으며, 이번 검증은 실제 사용자 HealthKit 저장소의 완전성이나 실기기 지연 시간을 보증하지 않는다. HealthKit 기록을 CloudKit으로 일괄 복제하는 변경도 아니다.
