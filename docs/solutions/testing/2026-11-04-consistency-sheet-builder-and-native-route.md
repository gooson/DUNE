# Consistency sheet builders and bounded native entry traversal

## Problem

A stronger consistency explanation must preserve its native sheet and describe qualifying workout days accurately. The first actual target compilation found a stored `StandardCard` builder capturing a non-escaping helper parameter. Syntax-only parsing could not establish the type-checking contract. After correction, maximum text exposed a separate entry issue: 30 root scrolls left the real information button below the viewport in a document over 20,000 points tall. A later normal case was interrupted by disk exhaustion; its partial xcresult could not support aggregate case counts.

## Solution

Declare the local builder `@ViewBuilder content: @escaping () -> Content` because the card stores it. Preserve all data calculations, icons, original content and native detents. State the existing per-workout 20-minute qualification and monthly default of 16 qualifying days; register the three manual en/ko/ja sentences and audit all 18 literals.

Keep `openActivityInfo`'s existing 30-swipe default and pass a bounded 40 only for A18 MAX. The fresh successful run reached the entry after 32 real root swipes. Initial captures precede native expansion, full-label predicates preserve long copy, and viewport/overlapping-interval checks verify readable content without shrinking fonts. Native dismissal and Activity return remain asserted; genuine normal return images are distinct from a MAX lock-screen capture that is excluded as visual proof.

Remove only verified unused compilation caches belonging to this chat's already merged worktrees, preserving their Logs/raw results and the current incremental cache. Record capacity recovery and check available space before further native runs. At final source d91f6248, five current cases passed across four serial runs, with independent selected PNG/AX and stage-preservation review. Preserve the earlier compilation archive's null UI counts and the second partial run's observed MAX failure/normal incompletion separately; do not invent a historical aggregate.

## Prevention

Distinguish Swift syntax parsing from target compilation, source review from actual native behavior, and incomplete SDK output from verified case counts. Derive route bounds from matching font/device state; comparing pre-relaunch normal frames with MAX frames cannot establish swipe displacement. Archive a completed or partial run fully before editing source or another test can prune SDK results.

Generate pin manifests from actual bytes and check literal lengths and referenced-file equality before dispatch. Private audit scripts also need those checks: malformed 63/65-character pins were rejected before archive/device actions and corrected without consuming new native execution. Preserve old controls and failed evidence rather than weakening comparisons.

## Lessons Learned

Use the affected original native selector to verify entry, reading and return together, and reuse its screenshots for the design map. Keep source/catalog facts and actual rendering as separate review gates. Documentation-only publication reuses unchanged tested bytes. No new Claude rule, unrelated app fix, full local regression or repeated permission question is required.
