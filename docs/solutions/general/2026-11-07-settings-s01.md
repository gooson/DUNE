# Solution: S01 설정 화면 개편

## Problem

기존 기능·기호·저장 동작을 보존하면서 설정 화면의 읽기 위계와 최대 글씨 배치를 개선해야 했다. S01–S04는 같은 타깃의 컴파일과 관련 검사를 묶고 화면별 PR로 분리했다.

## Solution

Native Form의 안전 영역 중복 가산을 없애고 DS 간격과 섹션 제목을 정리했다. 원래 Stepper·Picker·Toggle·아이콘·설명·알림·테마·동기화·권한 행동은 유지한다.

## Verification

iPhone 일반·MAX와 iPad 일반의 첫/끝 행 접근 및 기존 Stepper 왕복이 통과했다. 새 일반/MAX PNG·AX를 독립 검토했다.

네 공유 실행의 원본 수는 iPhone 최초8개 중4통과·4실패, iPhone 재검증4개 중1통과·3실패, iPad 최초5개 중2통과·3실패, iPad 재검증4개 중3통과·1실패다. 해당 S01의 관련 통과·실제 상태 증거만 사용하며 B07 전체·8개 검사 전부의 합격이 아니다. 별도 S03 iPad Save/reopen은 숫자 키보드 닫힘 대기 실패로 보류했다. Phone·iPad 각각 두 실패 기록과 P03·P08·H08 한도는 초기화하지 않았다.

독립 Security·Data Integrity·Architecture·Performance·Simplicity·SwiftUI·Apple UX·App Quality·최종 PR 소스 검토를 수행했다. S02 glyph P2는 수정 후 iPad 일반/MAX에서 닫혔으며 그 결과를 미캡처 Phone이나 다른 테마로 확대하지 않는다. 실제 앱 View 바이트가 같은 과거 통과는 화면별 source-adjudication에 한정해 재사용한다. UI 테스트의 앱 컴파일을 재사용하고 문서 단계에서 다시 빌드하지 않았다. 문자열·모델·동기화·입력 검증 로직은 변경하지 않았다. Watch·Vision·widget은 이 View의 소비자가 아니므로 로컬 실행을 추가하지 않았다.

## Evidence / Limits

[실제 PNG·AX·변경 전 비교](../../design/full-redesign-map/review/settings-s01-2026-11-07/index.html)에 소스·기기·selector·시각·이미지/AX 해시·원래 실패 수를 보존했다. 원래 PNG는 before, 실패한 흐름은 diagnostic, S02 수정 전 이미지는 superseded로 구분했다. 실제 맵과 Settings 보드는 미검증 화면을 현재 캡처로 표시하지 않는다.

Duo는 기존 전용 UDID가 사라진 뒤 필요한 캡처를 위해 빈 소유 기기 하나만 준비했으나 Data Migration Failed가 재현돼 SDK를 시작하지 못했다. 등록 단계 FD 오류와 부팅 실패 원본을 보관하고 그 소유 기기만 표준 경로로 정리했다. 접힘·펼침의 현재 PNG/AX는 없고 역사적 이미지는 미갱신으로 표시한다. 새 기기 준비는 원본 자료 복구를 뜻하지 않으며 l03/batch04 실종 원인·복구도 여전히 미확인이다.

입력과 선택은 --ui-reset/--seed-mock의 소유 시뮬레이터와 in-memory 저장소에서 검사했다. 실제 iCloud/HealthKit/알림 권한 행동·Watch 전송·다른 언어·테마·다크·프로세스 재실행 영속성·전체 회귀의 증거는 아니다. 새 카메라·센서·데이터 경로는 없다.

## Prevention

- 고정 아이콘 열에는 자동 확대 glyph의 실제 frame이 밖으로 나오는지 MAX PNG/AX를 대조한다.
- lazy Form의 화면 밖 행은 bounded scroll 뒤 접근한다.
- 검색 중 native Close와 실제 Back을 구분하고, iPad AX가 숨긴 Back은 측정된 기기 전용 좌표와 복귀 assertion으로 확인한다.
- iPad 부동 숫자판이 다음 필드를 덮는지 확인한다. 다른 필드의 키 입력을 저장 성공으로 취급하지 않는다.
- 과도한 추가 경로 때문에 통과한 화면을 반복 실행하지 않으며 실패 기록·소스·필수 범위를 분리한다.
