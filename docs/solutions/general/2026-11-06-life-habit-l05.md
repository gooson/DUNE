# 습관 이력에서 실제 습관과 기록을 하나의 스크롤로 읽기

## Problem

기존 L05의 기록·기간·동작은 유지하면서 상세 화면 간 시각 위계를 통일해야 했다. 짧은 sheet와 최대 글씨에서는 헤더와 기록이 같은 가용 높이를 나눠 쓰므로, 제목의 존재만 확인하는 검사는 실제 행·날짜·닫기 가시성을 증명하지 못한다.

## Solution

`DUNE/Presentation/Life/LifeView.swift`: 원래 습관명·아이콘·기록 수와 완료/건너뜀/미룸·날짜/값·늦은 기록을 보존하고 HeroCard와 기존 Past Record·Close를 한 ScrollView 안에 배치했다.

기존 조회·정렬·날짜 범위·합계·비율·저장·내비게이션을 바꾸거나 합성 표시 값을 production에 추가하지 않았다. 관련 기존 UI selector와 두 combined MAX selector를 공유하며, combined MAX 메서드는 두 App 소유 화면이 모두 게시된 PR부터 포함한다. 첫 화면 PR에 아직 존재하지 않는 다음 화면의 AX ID를 요구하는 새 nightly 검사를 넣지 않는다.

## Prevention

큰 헤더와 중첩 스크롤 대신 한 소유 스크롤을 사용한다. 빈 기록도 동일한 닫기와 선택적 과거 기록 경로를 보존한다.

## Lessons Learned

앱 상태를 새로 계산하지 않고 기존 값·원래 SF Symbol을 더 잘 읽히도록 배치한다. SDK 성공, 실제 PNG/AX의 시각 검토, 실제 디자인맵 갱신, PR 머지는 서로 다른 게이트다. 실패한 준비·SDK aggregate와 이후 개별 성공을 구별한다.
