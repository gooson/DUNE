# Solution: 습관 새로 만들기·편집에서 현재 선택을 읽기 쉽게 표시하기

## Problem

### Symptoms

기존 습관 Form은 이름·아이콘·유형·목표·주기·시작점·시간·알림·자동 연결을 제공했지만, 상단에서 현재 새로 만들기/편집 상태와 입력 중인 이름·아이콘 범주를 한눈에 읽기 어려웠다. 아이콘 4열 고정 격자는 큰 글씨에서 범주명이 좁은 폭을 나눠 써야 했다. 이는 기존 화면의 표현상 문제이며 저장 데이터 오류로 확인된 것은 아니다.

### Root Cause

Form의 각 섹션은 정확한 입력 역할을 했으나 화면 전체의 상태 요약은 없었다. 아이콘 선택 레이아웃은 글씨 크기와 관계없이 네 열을 유지했다.

## Solution

### Changes Made

| File | Change | Reason |
| --- | --- | --- |
| `HabitFormSheet.swift` | Form 맨 앞에 `HeroCard`를 두고 원래 선택한 아이콘 범주, `New Habit`/`Edit Habit`, 입력 중인 실제 이름을 표시했다. | 현재 편집 상태를 기존 입력과 연결한다. |
| `HabitFormSheet.swift` | 아이콘 목록을 `GridItem(.adaptive(minimum: ...))`로 배치하고 이름에 자연 높이를 허용했다. 선택 상태의 AX trait와 버튼 ID를 더했다. | 큰 글씨에서 모든 원래 아이콘 선택지를 유지하며 줄바꿈과 접근성 확인을 허용한다. |
| `LifeRegressionTests.swift` | 새 습관과 기존 습관의 입력·선택·저장 경로, 접힌 Duo MAX에서 마지막 아이콘과 취소 경로의 선택 검사를 추가했다. | 실제 Form 상태와 입력 동작을 대상으로 확인한다. |

### Key Code

```swift
Text(formHeroTitle)
    .accessibilityIdentifier("habit-form-hero-title")
if !viewModel.name.isEmpty {
    Text(viewModel.name)
        .accessibilityIdentifier("habit-form-hero-name")
}

GridItem(.adaptive(minimum: dynamicTypeSize.isAccessibilitySize ? 108 : 72))
```

기존 `LifeViewModel` 입력 바인딩, 유효성 검사, `onSave()`/dismiss, 모든 `HabitIconCategory.allCases` 순회는 유지했다. 새 도메인 값이나 저장 분기를 만들지 않았다. 밝은 모드의 범주색만 카드 위에서 읽히도록 어둡게 조정했다.

## Prevention

폼 상단에 현재 값을 요약할 때 별도 상태 복사본을 만들지 않고 기존 binding에서 직접 읽는다. 큰 글씨에서 고정 열 수와 고정 높이를 피하고, 원래 선택지의 마지막 항목까지 접근·선택 가능한지 실제 AX와 PNG로 확인한다. HeroCard 전체에 AX ID를 붙여 자식 텍스트·버튼을 숨기지 않는다.

## Lessons Learned

요약 카드는 입력 자체를 대체하지 않는다. 현재 Form의 상태를 그대로 읽으면 저장 의미를 바꾸지 않고 화면 위계를 보강할 수 있다.

## Validation status

L02의 9개 메서드·프로필 조합을 선택 SDK 결과와 독립 PNG/AX 리뷰로 확인했다. 이 배치의 총 23개 조합과 기존 실패·원인별 재시도는 [L02 실제 화면·원본 출처](../../design/full-redesign-map/review/l02-habit-form-2026-11-06/index.html)에 구분했다. 해당 네 기본 프로필의 actual-map 행을 갱신했다. 전체 회귀·Dark·실기기·VoiceOver·최종 PR HEAD 실행·CI·머지는 주장하지 않는다.
