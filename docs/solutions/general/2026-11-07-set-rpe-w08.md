# W08 세트 보조 화면 읽기 배치

## Problem / Solution

MAX에서 실제 RPE 값과 설명을 세로로 배치하고 원래 다섯 범주를 가로로 이동해 읽게 했다. 6–10, 0.5 단계, Binding·활성화·지우기·도움말은 유지했다. 원래 세트 입력·완료 및 Compound 세션 경로를 유지했다. 배치/테마 시안을 먼저 기록하고, 실제 앱 화면은 별도의 새 PNG/AX로 검증했다.

## Actual verification

Compound 경로에서 첫 세트를 완료해 W07 휴식 카드의 +30s/Skip, W08 완료 세트의 활성 RPE/범주, W09 도움말의 마지막 범위와 Done을 확인한다. Phone MAX와 iPad 일반/MAX의 통과한 selector에 연결된 새 PNG/AX만 after로 표시한다. Phone 일반은 Skip AX 조회 실패로 W08/W09까지 도달하지 못해 실제 화면 맵의 이전 PNG를 유지하고 미갱신으로 기록한다. [원본 실행 수·PNG/AX·소스 검증](../../design/full-redesign-map/review/set-rpe-w08-2026-11-07/index.html)에 중간 실패/진단도 그대로 남긴다. 같은 앱 파일의 검증된 해시 0c438d0b6858f781386d906ba928612a2ce6aa9b9831ac8683cad640f264bff0를 분리 PR에서도 확인했다.

## Review / Limits

독립 Security, Performance, Architecture, Data Integrity, Simplicity, SwiftUI 관점을 확인했다. Agent-Native는 앱 코드 변경에 해당하지 않는다. 새 P1/P2 여부와 실제 기기별 결과는 갤러리의 원본 receipt 및 최종 게이트 문서에 기록한다. Duo 접힘/펼침은 현재 소스 캡처가 없으면 역사적 PNG를 그대로 두고 미갱신으로 표시한다. MAX에서 특정 스크롤 위치의 캡처가 전체 화면을 한 번에 보여준다는 뜻은 아니다.

## Prevention

Compound가 실제 W07 소비자임을 확인하고 Template quick path의 다른 휴식 UI를 대신 쓰지 않는다. 런타임 세트 번호 AX와 UUID를 혼동하지 않는다. 변경된 가로 범주는 시작과 마지막 위치를 모두 캡처한다. 시트는 처음 상태와 마지막 범위/RIR을 읽은 상태를 구분한다. 실패한 selector의 캡처는 after로 승격하지 않는다. 결합 UI harness는 W07/W08이 main에 온 뒤 W09 PR에 한 번만 넣는다.
