# Solution: 지난 날짜 습관 기록에서 선택 날짜를 입력과 함께 확인하기

## Problem

### Symptoms

지난 날짜 기록 Form은 습관·날짜·기존 합계·새 입력을 제공했지만, 선택한 날짜가 상단의 현재 작업 맥락으로 드러나지 않았다. 읽기·물 마시기·체크형 습관의 날짜와 입력 형식은 서로 달라 큰 글씨에서 헤더와 실제 필드가 함께 보이는지 별도로 확인해야 했다. 기존 날짜/합계 계산의 데이터 오류가 관찰된 것은 아니다.

### Root Cause

기존 Form 섹션은 각각의 값을 표시했으나 선택 날짜를 화면의 첫 정보로 묶지 않았다. 별도 헤더 상태를 만들면 DatePicker와 표시가 어긋날 수 있으므로 원래 `selectedDate`를 재사용해야 했다.

## Solution

### Changes Made

| File | Change | Reason |
| --- | --- | --- |
| `HabitPastRecordSheet.swift` | 기록 가능한 습관이 있을 때만 Form 맨 앞에 HeroCard를 넣고 기존 선택 습관 아이콘과 `selectedDate`를 표시했다. | 날짜 선택과 기록 대상의 현재 상태를 첫 화면에서 읽는다. |
| `HabitPastRecordSheet.swift` | 날짜 텍스트에 리프 AX ID를 붙이고 아이콘은 장식으로 숨겼다. 밝은 모드의 범주색을 읽기 쉽게 조정했다. | 실제 표시 날짜를 MAX와 화면별 AX에서 검증한다. |
| `LifeFlowUITests.swift` | 열기/취소 시 오늘 기록 불변, Read의 어제 합계 30→40 교체, 세 기록 종류의 MAX 필드 접근 검사를 추가했다. | 기존 교체/저장 의미가 UI 표현 변경 뒤에도 유지되는지 확인한다. |

### Key Code

```swift
Text(selectedDate, format: .dateTime.year().month().day())
    .accessibilityIdentifier("habit-past-record-hero-date")
```

기존 `eligibleHabits`, `selectedHabit`, 허용 날짜 범위, `existingLogs`/`existingTotal`, 입력 파싱·검증, 다음 예정일 미리보기, `onSave` 결과와 Cancel은 변경하지 않았다. 새 날짜 계산이나 합성 기록을 production에 추가하지 않았다.

## Prevention

날짜 기반 입력의 요약은 DatePicker와 동일한 상태를 직접 읽는다. 테스트는 고정 달력 날짜를 가정하지 않고 표시된 날짜를 확인한다. 기존 `--ui-hero-rhythm-fixtures`로 과거 날짜가 가능한 습관과 어제 Read 기록을 준비하고, 저장 뒤 어제 합계의 교체와 오늘 값의 불변을 따로 검증한다. 새 화면 캡처는 이전 actual-map PNG와 구분한다.

## Native numeric input and lazy Form

네이티브 숫자 키보드에서는 공통 텍스트 입력의 Cmd-A와 Delete 한 번이 기존 `30`을 온전히 지우지 못했다. 검사에서는 실제 기존 글자 수만큼 native Delete를 입력하고 빈 값과 `40`을 확인했다. 접힌 Duo에서는 키보드가 Form 하단을 가리므로 숫자 입력 필드를 소유한 Form을 식별하고, 실제 창·내비게이션·키보드와 교차하는 가시 영역 안에서만 bounded drag로 Save를 드러낸다. 프레임이 유효하고 해당 내비게이션 안에 있는지 먼저 확인한 뒤 hittability를 조회한다. 이 보완은 UI 검사에만 있으며 앱 저장 의미나 공통 입력 helper를 바꾸지 않는다.

작은 medium sheet의 DatePicker는 화면 아래에서 lazy 생성될 수 있다. 처음 보이는 hero 날짜를 캡처한 뒤 기존 Form reveal helper로 실제 날짜 컨트롤을 드러내고 검사한다. 단순히 하단 행의 초기 AX 존재 여부를 요구하면 앱의 정상 입력을 실패로 오판할 수 있다.

## Lessons Learned

지난 기록의 시각적 요약은 입력 중인 실제 날짜를 설명해야 한다. 기존 Form 데이터를 그대로 투영하면 시각적 위계를 높이면서 날짜·수치 처리 경계를 보존할 수 있다.

## Native review limits

접힌 Duo 최대 글씨의 기존 Water 단위 `glasses`는 좁은 폭에서 단어 중간으로 줄바꿈된다. 값·단위·필드와 Cancel은 읽고 조작할 수 있었으며 기존 단위 레이아웃의 P3 표현 보완으로 남겼다. 새 앱 저장 오류나 필수 조작 실패로 분류하지 않는다.

## Validation status

L09의 9개 메서드·프로필 조합을 선택 SDK 결과와 독립 PNG/AX 리뷰로 확인했다. 이 배치의 총 23개 조합과 기존 실패·원인별 재시도는 [L09 실제 화면·원본 출처](../../design/full-redesign-map/review/l09-habit-past-record-2026-11-06/index.html)에 구분했다. 해당 네 기본 프로필의 actual-map 행을 갱신했다. 전체 회귀·Dark·실기기·VoiceOver·최종 PR HEAD 실행·CI·머지는 주장하지 않는다.
