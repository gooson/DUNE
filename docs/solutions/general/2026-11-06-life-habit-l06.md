# 관리에서 연 습관 기록의 헤더와 동작을 분리해서 검증하기

## Problem

기존 L06의 기록·기간·동작은 유지하면서 상세 화면 간 시각 위계를 통일해야 했다. 짧은 sheet와 최대 글씨에서는 헤더와 기록이 같은 가용 높이를 나눠 쓰므로, 제목의 존재만 확인하는 검사는 실제 행·날짜·닫기 가시성을 증명하지 못한다.

## Solution

`DUNE/Presentation/Life/HabitManagementView.swift`: 원래 cachedLogSnapshots와 sortedEntries/action/date/value 계산을 유지하고 실제 습관 아이콘·이름·History를 HeroCard로 읽는다. 제목/Close/기록 action/date는 실제 리프 식별자로 구별했다.

기존 조회·정렬·날짜 범위·합계·비율·저장·내비게이션을 바꾸거나 합성 표시 값을 production에 추가하지 않았다. 관련 기존 UI selector와 두 combined MAX selector를 공유하며, combined MAX 메서드는 두 App 소유 화면이 모두 게시된 PR부터 포함한다. 첫 화면 PR에 아직 존재하지 않는 다음 화면의 AX ID를 요구하는 새 nightly 검사를 넣지 않는다.

## Prevention

부모 카드에 식별자를 붙여 텍스트·버튼을 숨기지 않는다. MAX에서 이름·날짜와 Close를 원래 기록을 소유한 ScrollView 안에서 드러낸다.

## Lessons Learned

앱 상태를 새로 계산하지 않고 기존 값·원래 SF Symbol을 더 잘 읽히도록 배치한다. SDK 성공, 실제 PNG/AX의 시각 검토, 실제 디자인맵 갱신, PR 머지는 서로 다른 게이트다. 실패한 준비·SDK aggregate와 이후 개별 성공을 구별한다.
