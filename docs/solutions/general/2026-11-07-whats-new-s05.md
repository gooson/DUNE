# Solution: S05 새 소식 읽기 배치

## Problem

원래 release/feature 콘텐츠·아이콘·화면 순서·dismiss 동작을 보존하면서 넓은 화면의 읽기 폭과 최대 글씨 배치를 개선해야 했다.

## Solution

release 목록과 각 feature 행을 접근성 글씨에서 세로로 배치하고, 버전과 원래 요약이 감싸지도록 했다. 일반 글씨 행과 자동 Done은 유지한다. 두 화면에 680pt 최대 읽기 폭과 size-based bounce를 적용했다. 문자열·release 순서·automatic/latest와 manual/all 구분·읽음 처리·callback·저장·원래 아이콘·아트워크 분기는 변경하지 않았다. 배치/테마 맵을 구현 전에 커밋했고 같은 파일의 독립 View 구간으로 화면별 PR을 나눈다.

## Verification

공유 iPhone 최초 실행은 새 empty-fixture 검사 클래스가 SeededUITestBaseCase 전용 함수를 호출하여 컴파일에서 실패했고 실행된 테스트는 0개다. 필요 없는 호출 하나를 제거한 동일 b08-phone의 조건부 재검증에서 정확한 3개가 모두 통과했다. iPad는 manual 목록/상세의 일반·MAX 두 검사를 묶어 실행했다. 실제 통과 수와 원본 실패·소스·기기는 [새 PNG/AX 갤러리](../../design/full-redesign-map/review/whats-new-s05-2026-11-07/index.html)의 receipt와 manifest가 기준이다. 정상 진입·native Back·자동 Done, 버전·전체 제목·요약·기존 hero artwork를 확인했다. 같은 타깃 XCTest 컴파일을 재사용했으며 별도 반복 빌드나 전체 로컬 회귀는 실행하지 않았다.

독립 Security/Data Integrity/Architecture/Performance/Simplicity/SwiftUI/Apple UX/App Quality 소스·PNG·AX 검토를 수행했다. 새로 도입된 P1/P2는 없다. 새 UI 검사 클래스는 기존 SettingsSmokeTests와 helper를 바꾸지 않는다. Watch/widget 데이터나 화면은 소비자가 아니며 부가 로컬 실행을 추가하지 않는다.

## Evidence / Limits

실제 맵의 iPhone/iPad 일반 PNG·AX와 별도 MAX 갤러리를 갱신했다. Duo는 새 빈 소유 기기에서도 Data Migration Failed가 재현된 뒤 SDK 전 실패하여 현재 캡처가 없고, 역사적 PNG를 완료 증거로 취급하지 않는다. 그 실패 기기는 로그 보존 뒤 정리했다. 원래 l03/batch04 실종 원인과 복구 여부는 여전히 미확인이다. P03·P08·S03·H08의 실패 횟수와 한도는 유지한다.

관찰한 영어·밝은 테마·현재 0.8.0/ios27Support 표본만 검증했다. 다른 언어·다크·다른 release/asset branch·VoiceOver 실제 청취·외부 영속성의 증거는 아니다. MAX에서 반복되는 symbol hero 장식 제목은 기존 고정 높이·lineLimit 소스 때문에 말줄임이 보인다. 원래 아트워크는 변경하지 않았으며 별도 의미 있는 제목·요약은 전체를 읽을 수 있다. 모든 장식 텍스트가 잘리지 않는다고 주장하지 않는다.

## Prevention

기존 base class 전용 helper의 가시성을 먼저 확인한다. 문법 검사만으로 타입 검사 성공을 주장하지 않는다. 일반/MAX의 native PNG와 AX를 함께 보고 변경된 View 구간의 byte 동일성을 확인해 검증을 재사용한다. source-only 시안과 역사적 PNG는 새 native 증거가 아니다.
