# T06 체지방률 조사 참고값 구현 계획

## 배경과 범위

연령대별 신체 수치를 살펴보고 싶다는 요청의 후속 작업이다. 체중·BMI의 기존 미국 NHANES 2021–2023 비교는 유지하고, 체지방률 상세에는 미국 성인 DXA 조사 평균을 선택적으로 제공한다. 인바디 자료나 한국인 기준, 적정 체지방 범위로 표시하지 않는다. H04의 두 지표 시계열 비교와는 별도 PR이다.

실제 기반은 A21 머지 `e99a16e98ba99f48aaa1fe377b37c26751bcefb0`이며, 같은 소유 워크트리를 재사용한다. 원래 개편 화면 67개에 더해 별도 관리하는 후속 작업 1개다. 이 문서 작성 시 앱 구현·단위 검사·새 네이티브 캡처는 아직 수행 전이다. 기존 사용자 승인으로 `/run`을 계속하며 추가 승인 대기는 만들지 않는다.

## 자료와 표현 계약

[CDC/NCHS Series 11 No. 250](https://www.cdc.gov/nchs/data/series/sr_11/sr11_250.pdf)의 Table 3, 인쇄 12쪽/PDF 18쪽을 사용한다. NHANES 1999–2004의 미국 성인 전체 인종·민족 DXA 가중 평균이다. Table 2의 지방량 kg와 구분하며, 원문과 독립 자료 검토에서 아래 여덟 값을 대조했다.

| 자료상 성별 | 20–39세 | 40–59세 | 60–79세 | 80세 이상 |
|---|---:|---:|---:|---:|
| 남성 | 26.1% | 28.6% | 30.8% | 30.7% |
| 여성 | 37.8% | 40.5% | 42.4% | 40.4% |

- 사용자가 기존 연령 구간·조사 성별을 직접 선택한다. 30–39세 선택은 실제 조사 구간인 **20–39세**로 명시하고 보간하지 않는다. 미선택·잘못된 저장값을 임의의 프로필로 바꾸지 않는다.
- 개인 기록과 조사 평균은 별도 레이블·원래 지표 아이콘으로 표시한다. 같은 차이 막대·점수·건강 판정색·백분위는 만들지 않는다. 측정 방식이 불명확하거나 DXA와 다를 수 있다는 설명을 값보다 먼저 표시한다.
- HealthKit의 비율은 기존 읽기 경로에서 이미 ×100, 쓰기 경로에서 ÷100 처리한다. 이 카드에는 기존 `%` 단위의 percentage point를 전달하며 다시 곱하지 않는다. 비유한 값·0 미만·100 초과·다른 단위는 개인 값 미제공 상태로 처리하고 0으로 대체하지 않는다.
- 원문 출처 시트에 모집단·연도·DXA·가중 평균·임신 등 제외 조건·결측치 대체와 비보증 설명을 둔다. 외부 보고서는 명시적인 링크 조작으로만 연다.
- 체중·BMI의 계산·단위·2021–2023 출처, 기존 공통 선택 저장 키, 제지방량 미지원 상태는 유지한다. 기록이 아예 없어 상세에 진입하지 않는 경로를 새로 만들지 않는다.

## 접근 방법과 대안

`BodyFatSurveyReference`라는 작은 불변 Domain 모델을 별도로 둔다. 기존 `BodyPeerReference.compare`에 체지방을 추가하면 공통 연도와 직접 차이 계산을 혼용하게 되므로 확장하지 않는다. 기존 `BodyPeerComparisonCard`의 선택/출처 시트·아이콘 행·DS 간격·숫자 포매터를 재사용하고 접근성 글씨에서는 연령/성별과 값 행을 세로로 배치한다. 통계 참조를 새로운 건강 권고나 자동 프로필 입력으로 만들지 않는다.

## 구현과 검증 순서

1. 원문·기존 호출부·단위·선택 저장 키·시안 계약을 확인한다. 공개 계획과 레이아웃/테마의 후속 범위를 먼저 갱신한다.
2. 독립 검토한 모델·뷰·카탈로그·단위/UI 검사 제안을 실제 머지 기반에 적용한다. 원래 아이콘과 기존 체중/BMI/제지방 분기의 차이를 확인하고 프로젝트를 표준 후처리로 재생성한다.
3. `BodyPeerReferenceTests`와 `BodyFatSurveyReferenceTests`만 실제 실행한다. 새 모델이 DUNEVision의 재귀 Domain 소스에도 포함되므로 Vision은 빌드만 한 번 확인한다. Watch는 해당 모델/뷰를 포함하지 않으므로 별도 Watch 실행은 하지 않는다.
4. 정확한 새 소스 커밋과 실행기 파일 해시를 고정한 뒤, 전용 기기 한 개씩 다음 핵심 UI 5건을 네 번 실행한다. 동일 증거는 이후 단계에서 재사용한다.

| 기기·자세 | 선택한 검사 |
|---|---|
| Duo 접힘 | `testBodyFatDXASurveyFlow` + `testBodyFatDXAMaximumAccessibility` |
| 같은 Duo 펼침 | `testBodyFatDXASurveyFlow` |
| 일반 iPhone | `testBodyFatDXASurveyFlow` |
| iPad mini (A20 Pro) | `testBodyFatDXASurveyFlow` |

테스트 클래스는 `DUNEUITests/MetricDetailRedesignTests`다. 일반 흐름은 실제 미선택·Apply 비활성·취소를 확인한 뒤 30–39세/남성 선택, 실제 20–39세/26.1%·개인 17.8%의 구분, 측정 방식 안내, 출처/Done, 실제 Today 복귀와 다시 열었을 때 선택 유지를 확인한다. Duo 접힘의 어두운 최대 접근성 글씨는 실제 경고와 각 값의 도달 가능한 viewport·네이티브 닫기를 확인한다. 소스 단위 `%` 가드와 차이 미생성은 소스 검토 및 유효 `%` 네이티브 경로의 근거이며, 잘못된 단위를 단위 테스트로 실행했다고 주장하지 않는다.

5. 실행별 원본 결과·PNG·AX·소스·기기 UID·Duo 자세/활성 LCD를 봉인하고 독립 소스/실제 화면/발행 검토를 받는다. 기존 실패는 보존하고 원인 변화가 있는 필요한 검사만 재시도한다.
6. 문서화와 화면별 PR 생성·통상 머지를 마친다. 사용한 소유 기기만 삭제하고 다음 화면에서 재사용할 워크트리·캐시는 유지한다. 다른 채팅 소유·불명확한 워크트리를 우회 삭제하지 않는다.

## 실제 화면과 자료의 한계

기본 실제 맵의 T06 대표는 HRV다. HRV PNG·행·보드를 체지방 화면으로 덮어쓰지 않고 네 기기의 체지방 후속 갤러리를 포털에 연결한다. 과거 `0dc77dc4`/`f9f1d852`의 체지방 초기/하단 이미지는 iPad에만 있으며 해당 PNG의 이력 참고로만 쓴다. 대응 AX가 없고 이번 조사 카드의 원본 상태가 아니므로, iPhone/Duo의 기존 화면이나 같은 조건의 전후 검증으로 확대하지 않는다. 이전 이미지를 이번 새 화면의 완료 증거로 재사용하지 않는다.

네이티브 5건과 별도 Vision 빌드·필요한 단위 검사·카탈로그 검사만 약속한다. 모든 지표·언어·플랫폼·VoiceOver 음성의 전체 검증을 약속하지 않는다. 실제 실행 결과와 미검증 범위는 완료 문서에 별도로 기록한다.

## 확신도

자료 원문·단위 경로·기존 소비자를 독립 검토했고 제안 소스·번역·UI 계약의 미해결 P1/P2/P3는 없다. 따라서 설계 확신은 높지만, 실제 컴파일·동작·캡처 결과는 이후 게이트에서 확인한다.

## Vision 검증 범위 조정

계획한 전체 DUNEVision 빌드 한 번은 **실패**했다. 기존 `DailyDigestScheduler`, `ExerciseVariantMigration`, `HealthKitObserverManager`가 Vision 타깃에서 제외·누락된 파일의 타입을 참조했다. 독립 검토에서 실패 파일·타입 정의·`project.yml`이 기반 `e99a16e9`와 동일함을 확인했다. 기반 전체 빌드를 다시 실행한 결과는 아니며, 새 모델 진단이 없다는 사실만으로 새 코드의 컴파일 성공을 추정하지 않는다. 기존 실패 로그와 실행기 기록을 보존하고 이 후속 작업에 무관한 Vision 소스 구성을 함께 수정하지 않는다.

변경 범위의 컴파일은 별도 제한 검사로 확인했다. 실제 XRSimulator 27.2 SDK, `x86_64-apple-xros27.0-simulator`, Swift 6·strict concurrency에서 `BodyPeerReference.swift`와 새 `BodyFatSurveyReference.swift` 두 파일만 typecheck하여 종료 코드 0을 확인했다. 이는 **분리한 모델 typecheck 통과**이며 전체 DUNEVision 빌드·실행·UI 통과가 아니다. 전체 빌드 실패는 계속 별도로 보고한다. iOS의 선택한 단위·네이티브 검사 게이트는 그대로 유지한다.

## 2026-11-05 실제 선택 검사와 별도 갤러리

[체지방 DXA 실제 화면 갤러리](../design/full-redesign-map/review/t06-body-fat-dxa-native-2026-11-05/index.html)는 선택한 5개 UI case의 32개 PNG/AX 쌍을 기기별로 보존한다. Duo 접힘의 일반 흐름은 `113b87cd` 실행 전체가 2건 중 1건 실패한 기록에서 해당 case만 Passed였고, 최대 글씨 흐름은 최종 소스 `2f40e909`에서 별도 1/1 Passed였다. Duo 펼침·일반 iPhone·iPad의 일반 흐름도 `2f40e909`에서 각각 1/1 Passed였다. 하나의 Duo 접힘 2/2 실행이나 원래 파이프라인의 성공을 뜻하지 않는다.

12개 논리 단위 검사의 2개 suite 통과는 이전 `1480a066` 소스의 복구된 결과다. 변경되지 않은 모델·소비자 바이트 검토를 통해 재사용 범위를 정했으며 새 소스에서 단위 검사를 다시 실행했다고 표기하지 않는다. 전체 Vision 타깃은 기존 의존성 문제로 실패했고, 두 모델의 분리 XRSimulator typecheck만 통과했다. 과거 iPad PNG 4개는 당시 상세 변형의 참고 자료이며 DXA 카드의 일치하는 이전 화면이나 AX 쌍이 아니다.
