# 아홉 작가 테마의 앱 적용

네 탭과 상세 화면은 승인된 `artist-editions.html`의 전폭 제목 배경을 사용한다. 건강 수치, 점수의 상태색, 실제 차트, 접근성 레이블과 화면 이동은 기존 네이티브 뷰가 담당한다. 애니메이션은 장식에만 적용한다.

## 구현 순서

1. 승인된 그림과 움직임만 네이티브 리소스로 렌더링한다. 각 테마는 고유 포스터와 반복 영상을 가진다. 화면 구조나 점수를 영상에 넣지 않는다.
2. 기존 배경 분배기에서 리소스를 찾고, 활성 화면에만 로컬 영상을 재생한다. 정지 포스터를 먼저 표시하고 동작 줄이기·비활성 상태에서는 플레이어를 해제한다. 라이트·다크와 제목 여백은 SwiftUI에서 처리한다.
3. 네 탭의 제목, 공유 상세와 예외 경로에 연결한다. 웰니스 등 첫 카드의 좌우 분할과 하단 전용 그림 영역을 제거한다. 공유 카드, 점수와 차트의 가독성은 각 테마의 표면과 기존 상태색으로 검증한다.
4. 공통 기반 다음에 테마별 자산과 변경만 독립 브랜치로 등록한다. 신규 선택 항목은 필요한 모든 소비자와 자산을 같은 PR에 담는다.

## 테스트 전략

- 번들 자산, 포스터·동영상 짝, 테마 설정과 색 대비는 관련 단위 selector로 검사한다. 앱 빌드·테스트는 기존 실행기와 이 작업 폴더의 기기를 사용한다.
- 루트 네 개와 컨디션, 운동 준비도, 운동 기록, 웰니스 점수, 수면 기록, 습관 주간 보고서를 핵심 경로로 캡처한다. 다른 push의 배경 소유자, 비어 있는 상태, 모달과 카메라·3D 전용 화면의 목적도 조사한다.
- 휴대폰 라이트·다크, iPad와 Duo의 실제 레이아웃, 변경한 Watch 선택·배경을 영향 범위에 맞게 점검한다. 테스트 영수증과 새 실제 화면만 디자인맵에 연결한다. 이미 통과한 동작은 다시 실행하지 않는다.

## 리스크와 경계 사례

테마 변경, 탭/상세 전환, 화면 복귀, 시트 위·아래에서 장식 재생기가 남지 않아야 한다. 파일 부재, 동작 줄이기, 큰 글씨에서도 읽기와 조작이 가능해야 한다. 기존 테마의 저장 키를 보존한다. 전체 화면 비디오/카메라, 지도, 3D 캔버스 등 고유 콘텐츠를 장식으로 덮지 않는다.
