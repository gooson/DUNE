# 운동 복원 및 Mac 표시 검증 계획

## 합격 기준

분실 복원, 기존 앱 업그레이드, Mac 열람은 각각 독립적으로 판정한다. 기존 iPad에 남아 있는 기록을 보거나 시뮬레이터에서 JSON을 다시 읽은 결과만으로 Apple 건강 iCloud 복원을 통과시키지 않는다. 합격에 사용한 빌드와 테스트 대상, 실제로 관찰한 값을 남긴다. 위치명, 좌표, 건강 데이터 원본, 계정 식별자는 저장소에 올리지 않는다.

| 검사 | 절차 | 합격 기준 |
|---|---|---|
| 원본 기준 | 연결된 iPad와 Mac에서 운동 ID, 날짜, 운동명, 세트 소유 관계를 읽기 전용으로 비교 | 수정 전후 운동·세트 전체의 필드 및 부모 ID 해시 일치. 신규 운동은 별도 비교 |
| 신규 iPhone 운동 | 앱에서 생성한 합성 근력 운동을 빈 저장소에서 HealthKit 원본으로 다시 읽기 | 운동 ID, 운동명, 세트 순서·중량·횟수가 일치. 재실행·재수신에도 한 벌 |
| 유산소 상세 | 실내 장소만 있는 운동, 경로만 있는 운동, 둘 다 없는 운동 비교 | 원본에 저장된 이름·좌표와 경로만 표시. 임의로 경로 생성 금지 |
| 기존 사용자 | 이미 저장된 운동, HealthKit 연결 기록, 메타데이터가 없는 과거 기록을 함께 열기 | 기존 연결 유지. 없는 세트·장소를 만들어 내지 않음 |
| 결합 순서 | HealthKit 우선, 앱 데이터 우선, 중복 수신, 오래된 자료 재수신 | 같은 논리 ID에 병합. 기록·세트 중복 없음 |
| 동기화 범위 | 앱 자체 iCloud 설정 ON/OFF, 앱 재시작, Watch·visionOS·위젯 저장 경로 검토 | 개인 운동·좌표·경로·세트는 앱 CloudKit으로 새로 전송되지 않음. 로컬 기록 유지 |
| Mac 실제 수신 | 동일 계정, 명시적 근처 전송 활성화, 서로 다른 기기에서 송수신 | 사용자가 지정한 날짜의 유산소·근력 세 행을 원본 ID로 비교. 누락·중복 0건 |
| Mac 실제 지도 | 같은 HealthKit ID의 실내 운동 상세를 양쪽에서 열기 | 같은 운동 ID, 장소명·핀 좌표 일치, 확대 가능한 지도. 위치 누락 화면은 실패 |
| 장애·보안 | 권한 거부, 계정 변경, 키체인 미사용, 중단·재시도, 잘린 패킷·잘못된 버전·중복 ID | 승인되지 않은 전송 및 부분 저장 없음. 다른 계정 캐시 노출 없음 |
| 오프라인 | 수신 후 원본 기기 연결 해제, Mac 앱 재실행 | 이미 수신한 범위가 보존되고 새 데이터 수신 여부와 구분됨 |
| 실제 분실 복원 | 원본 단말을 사용할 수 없는 상태에서 같은 계정의 별도 iPhone에 Apple 건강 데이터 복원. 빈 DUNE 저장소로 앱 실행 | 원본과 날짜·ID·세트·장소 대조. 실물 대상이나 인증이 없으면 미검증 처리. 사용 중인 사용자 기기 초기화 금지 |

## 실행 순서

1. PR의 실제 소스와 기기 목록을 확인한다. 기존 운영 기록과 원본 HealthKit은 임의 변경하지 않는다.
2. 건강 데이터 저장과 비건강 앱 설정을 분리하고 기존 저장소 접근을 점검한다.
3. 같은 운동을 식별할 수 있는 HealthKit UUID를 보존하고, 복원 가능한 정보와 과거 기록에 원래 없었던 정보를 구분한다.
4. Mac 표시를 위해 인증된 기기 간 읽기 전용 복사본을 사용한다. 이 경로를 분실 백업의 근거로 사용하지 않는다.
5. 변경된 경로에 해당하는 자동 검사와 실제 기기 검사를 순차 실행한다. 검증한 커밋을 PR에 포함하고 결과가 없는 항목은 미검증으로 표시한다. 병합은 별도다.

## 11월 23일 전환 계획과 연결한 실행표

각 행은 독립적으로 판정한다. 서명 검증은 설치의 전제이며 수신의 증거가 아니다. 테스트 계정 A·B는 서로 다른 계정, A1·A2는 동일 계정의 서로 다른 기기다. 분실 복원 시험은 A1의 네트워크를 끊고 A2가 빈 앱 컨테이너에서 시작한 사실을 기록한다. 개인 기기를 초기화하지 않는다.

| 전환 번호 | 실행 조건과 비교할 값 | 실패 시 처리 |
|---|---|---|
| 01–03 | 설치본의 번들·빌드·서명 환경, 모델별 저장 경로를 기록한다. 합성 운동 2개에 서로 다른 논리 ID, 동일 세션 ID, 세트, 메모, 위치, 첨부를 넣고 ID별 대조표를 만든다. | 숫자가 같아도 값·관계·첨부 해시가 다르면 실패 |
| 04–05, 08–10 | 실물 A1에서 OFF → 새 운동 → 재실행 두 번 → ON → A2 수신 → OFF. 각 단계의 Today 점수·시각, 위젯, 수면·체성분, 원본 해시와 원격 변경 유무를 별도로 기록한다. 권한 일부 거부·빈 결과도 반복한다. | 한 기기의 KVS 설정 변화만 보이면 기기 간 수신은 미검증 |
| 06, 11–14 | 실물 Watch에서 연결/단독 운동, 완료 직전 단절, Watch 앱 재실행, 재연결을 수행한다. 동일 완료 재전송, 서로 다른 동시 운동, 삭제 후 재전송, 구버전 페이로드를 대조한다. 루틴 수정·삭제 순서도 뒤집는다. | 운동 누락·중복·삭제 부활, 세트 연결 오류가 하나라도 있으면 전환 보류 |
| 07, 21, 23 | Mac·Vision에서 직접 조회 가능/불가능을 따로 확인한다. 새 Today 점수와 갱신 시각, 30일 이전 운동, 오래된 운동의 장소 수정, 같은 날 운동 여러 건을 확인한다. 수신 후 원본을 끄고 다시 연다. | 최신 시각이 갱신되지 않거나 과거 이력이 잘리면 해당 소비자 보류 |
| 15–17 | 구버전 저장소 전체 복제본으로 업그레이드, 잠금·쓰기 실패·중간 종료·재실행을 시험한다. 원격 전용/로컬 전용/충돌 표본을 구분한다. 복구를 두 번 실행해 두 번째 추가 0건, 기존 필드·부모 연결·첨부 보존을 확인한다. | 충돌·권한 거부·네트워크 장애는 오류로 표시. 메모리 DB에 성공 저장 표시 금지 |
| 18 | A1 없이 새 실물 iPhone에서 Apple 건강 iCloud 복원 후 DUNE을 설치한다. 운동·세트·운동명·장소·실제 경로·리워드를 원본에서 식별 가능한 항목별로 비교한다. 메타데이터를 넣기 전 생성한 운동은 별도로 분류한다. | 과거 원본에 없거나 복구 경로가 없는 필드는 복원 가능으로 표시하지 않는다 |
| 19–20 | A1→A2→A1에서 즐겨찾기와 카탈로그 루틴 생성·순서 변경·삭제. 오프라인 동시 수정과 quota 오류, 계정 교체 후 캐시 분리를 확인한다. 원격 필드 목록을 확인한다. | 자유 입력 이름·메모·실제 중량·개인 위치가 일반 설정에 포함되면 실패 |
| 22, 24 | 앱·위젯·App Intents 모두에서 저장소 선택을 확인한다. 전용 기기 전체 백업 후 신규 기기에 복원하여 DB·첨부·위젯·설정 각각 포함/제외를 실제 대조한다. | 제외 속성만 읽어서는 시스템 백업 시험 미검증 |
| 25 | 동의·설정·직접 복구·Mac 대기·저장소 오류 화면의 실제 표시와 동작을 비교하고 영향 기기 캡처를 갱신한다. 심사 설명과 개인정보 안내까지 대조한다. | 백업 실패를 완료로 표시하거나 실제와 다른 안내가 있으면 제출 보류 |
| 26–27 | 전용 계정에서만 구버전 재연결·원격 사본 정리와 재업로드를 시험한다. 최종 서명본 신규/덮어 설치 및 두 번째 실행 후 전체 기준표와 비교한다. | 운영 삭제·병합·제출은 이 검증의 일부가 아니다. 증거 없는 항목은 미실행으로 기록 |

실측 증거는 커밋/빌드, OS·대상, 시작 상태, 관측 시각과 값, 기대값, 판정으로 연결한다. 공유 로그에는 좌표·장소명·사용자 이름·건강 UUID를 넣지 않는다.
