# Activity 카드 배치 · Astra 자문과 타 앱 조사

[현재 비교 시안: Flow / Compact / Training](../theme-map/themes/dune-activity-redesign.html) · [카드별 표현 계약](activity-redesign-proposal.md)

사용자가 운동 꾸준함·훈련 부하·볼륨을 포함한 전체 카드 배치의 효율을 Astra에게 문의하고 다른 앱도 확인하도록 요청했다. `gpt-6-astra`, high의 읽기 전용 UX 자문을 받았으며 아래는 그 권고와 실제 코드·공식 공개 안내를 종합한 제안이다. 앱 전역 모델을 변경하지 않았다. 시안의 수치는 예시이고 앱 구현/실제 기기 캡처가 아니다.

## 결론

**상태 확인 → 운동 선택 → 기록·성취 → 누적 분석**을 기본 흐름으로 권한다. 기존 Compact의 색·타이포그래피·강조 표현을 유지하고 정보 순서를 바꾼 `Flow`를 비교안으로 추가했다. 현재 두 안과 나란한 선택지이며 승인 또는 네이티브 적용 완료가 아니다.

Flow는 준비도 다음에 근육 회복·부담 점검·추천 운동, 그 다음에 최근 운동·개인 기록·달성 이력을 둔다. 주간 수치·보고서·꾸준함·28일 부하·운동 구성은 이후에 읽는다. 사용자가 강조를 요청한 기록/달성·시간/칼로리·보고서 수치를 삭제하거나 하단의 하나의 접힌 ‘분석’에 모두 숨기지 않는다.

## 이름부터 실제 의미에 맞추기

| UI 이름 | 실제 데이터 | 이번 시안의 정리 |
|---|---|---|
| 운동 페이스 | 현재/최고 연속 운동일, 월 운동일 목표 | **운동 꾸준함**. 달리기 min/km와 구분한다. Flow에서는 월 목표를 먼저 보여 준다. |
| 훈련 볼륨 kg | 유효한 기록의 중량×횟수 합계 | **근력 볼륨 · kg**. 다른 운동의 시간·거리·생리적 부하와 합산하지 않는다. |
| 근육 지도 볼륨 | 부위별 주간 세트 수 | 모드 이름 **세트 수**, 0/1–5/6–10/11–15/16+ 범례 유지. |
| 훈련 부하 | 노력도/RPE/심박 기반 값의 일별 28일 흐름 | **훈련 부하 · 최근 28일**. kg 볼륨과 별개의 카드/단위로 유지한다. |
| 훈련 부담 | 최근 훈련량·운동 간격·피로 등을 평가한 수준 | **훈련 부담 점검**. 누적 부하 그래프나 근력 볼륨과 구분한다. |
| 마지막 운동 47분·220kcal | 최근 운동이 있는 날짜의 모든 HealthKit 운동 합계 | **최근 운동일 · 10.25 합계**. 숫자의 강조는 그대로 보존한다. |
| 운동 구성 30일 | 실제 `ExerciseMixService`는 오늘 포함 28일/4주 | **최근 28일 · 운동 횟수 기준**으로 바로잡는다. |

확인한 코드: `ActivityViewModel.invalidateWorkoutCache`, `computeWeeklyStats`, `GenerateWorkoutReportUseCase.computeStats`, `TrainingLoadService`, `ExerciseMixService.analyze`, `ConsistencyCard`.

특히 `lastWorkoutMinutes/Calories`는 단일 세션이 아니다. 하루 운동을 여러 번 하면 합계가 달라지므로 ‘마지막 운동’이라는 문구를 유지하려면 실제 집계를 바꾸어야 한다. 이번 작업은 현재 집계대로 캡션을 수정한다.

또한 DUNE의 부하는 effort/RPE와 심박 기반 TRIMP 중 가능한 출처를 사용한다. 타 앱의 최적 범위·수치·회복 판정을 그 값 위에 그대로 얹지 않는다. 향후 부하 상세에 계산 출처를 명시하는 것이 필요하다.

## Astra 권고와 이번 적용 범위

Astra는 주간 통계와 보고서를 하나의 시각적 묶음으로 줄이는 장기안을 권했다. 동시에 둘의 집계 계약을 먼저 맞춰야 한다고 지적했다. 이번에는 더 안전한 **순서 개선안**을 적용한다.

| 순서 | Flow의 카드 | 조치 |
|---|---|---|
| 1 | 운동 준비도 | 현재 점수·해석·세 구성 막대를 유지. 과거 7일 추세는 기존 Training처럼 펼쳐 본다. |
| 2 | 근육 회복 | 3D 없이 앞/뒤 지도, 회복/세트 수, 지도 아래 범례 유지. |
| 3 | 훈련 부담 점검 | 수준과 세 관측 근거를 보존한다. 불완전한 데이터를 낮은 부담으로 대체하지 않는 것이 네이티브 구현 조건이다. |
| 4 | 추천 운동 | 주간 분석보다 앞에 둔다. 검색·장소/장비·추천·루틴·템플릿·AI·전체 운동 경로 보존. |
| 5 | 최근 운동 | 최신 2개와 배지·HealthKit 연동·유효한 평균 심박을 노출. 이전 기록 펼침 유지. |
| 6 | 개인 기록 | 달성감을 주는 최고 값·개선량·날짜·출처를 펼쳐 둔다. |
| 7 | 달성 이력 | 개인 기록 바로 다음 독립 카드로 최신 이벤트를 보여 준다. |
| 8 | 최근 7일 운동 | 근력 볼륨·시간·칼로리·활동일·일별 시간을 보존한다. |
| 9 | 주간 보고서 | 요약·변화·하이라이트를 보존한다. 통계와 숫자를 임의 병합하지 않는다. |
| 10 | 운동 꾸준함 | 월 목표를 먼저, 현재/최고 연속일을 보조로 둔다. 휴식일이 있어도 성취를 지우지 않는다. |
| 11 | 훈련 부하 | 최근 운동일 시간/칼로리의 강조와 별도의 28일 부하 그래프 유지. |
| 12 | 운동 구성 | 최근 28일 종목 구성과 주요 근력 부위를 독립 요약으로 유지. |

넓은 폭에서는 준비도 전체 폭 → 왼쪽 근육/부담, 오른쪽 추천 → 최근 운동 전체 폭 → 개인 기록/달성 → 주간 통계/보고서 → 꾸준함/부하 → 구성 순서다. DOM/읽기 순서는 좁은 폭과 같다. 큰 글씨와 좁아진 iPad 창은 한 열이다. 카드 높이가 다르다고 읽기 순서를 바꾸는 masonry는 사용하지 않는다.

첫 1–2개 화면에서 상태와 운동 선택을 읽는 것을 목표로 하지만 큰 글씨까지 두 화면에 강제하는 높이 계약은 만들지 않는다. 수치·범례·행동을 축소해 그 목표를 맞추지 않는다.

## 아직 합치지 않는 이유

주간 통계와 보고서의 숫자가 비슷해 보여도 원천이 완전히 같지 않다. 주간 통계의 칼로리는 HealthKit 운동, 활동일은 수동+HealthKit 날짜를 사용하고 보고서는 전달받은 운동 기록을 집계한다. 현재 예시에서 3일·142분·12,480kg가 같다는 이유로 실제 데이터도 같다고 가정하면 안 된다.

나중에 하나의 ‘주간 요약’ 표면으로 통합하려면 기간 경계·수동/HealthKit 중복 제거·단위·비교 기간·결측 처리부터 합의한다. 준비 전에는 둘의 상세 목적지를 각각 보존한다. 통합 후에도 통계와 보고서의 목적지 두 개가 필요하면 별도 제목 헤더 링크로 분리해 중첩 버튼을 피한다.

## 다른 앱에서 확인한 점

확인일은 2026-10-26이다. 공개된 공식 안내와 제품 자료를 확인했으며 각 앱을 설치해 모든 상태를 직접 실행한 비교는 아니다. 아래 ‘DUNE에 적용’은 출처의 필수 규칙이 아닌 설계 판단이다.

| 앱 | 공식 안내에서 확인 | DUNE에 적용할 점 |
|---|---|---|
| Gentler Streak | 메인 Streak의 Activity Path 아래에 오늘 추천이 배치된다. | 상태를 읽고 운동을 고르는 경로를 가깝게 둔다. [공식 추천 진입 안내](https://docs.gentler.app/daily-workout-recommendations/how-to-find-and-understand-your-daily-workout-recommendation) |

관련 정보 묶기·우선순위·점진적 공개의 원칙은 [Apple Layout](https://developer.apple.com/design/human-interface-guidelines/layout)을 참고한다. 이 문서의 카드 순서·제목·월 목표 우선은 DUNE의 설계 판단이며 Apple의 강제 카드 규격으로 표현하지 않는다.

## 구현 전 상태 계약

- 전체 기록 없음: 준비도 대기 설명 다음 운동 선택/템플릿. 빈 분석 카드 여러 개를 쌓지 않는다.
- HealthKit 접근 제한이지만 수동 기록 존재: 수동 기록·PR·달성을 보존해야 한다. 현재 프로토타입의 접근 필요 fixture는 이 수동 기록 공존 상태를 별도로 검증하지 않았다.
- 일부 점수/심박 없음: 해당 값만 `—`/미표시. 기록 없음이 낮은 부담·0bpm·회복 완료를 뜻하지 않는다.
- 이전 비교 없음: 현재 값은 유지하고 가짜 +0% 비교를 만들지 않는다.
- 부하 계산 자료 없음: 유효한 시간/칼로리는 남기고 부하 그래프만 자료 부족을 표시한다.
- 높은 부담/부상 충돌: 추천 전 근거를 명확히 유지한다. 현재 Flow의 정상 fixture만으로 모든 위험 상태를 검증했다고 주장하지 않는다.

## 산출물과 검증 범위

`activity-redesign-fragment.html`/보존 HTML에 Flow를 추가하고 레이아웃/테마 맵에서 이 문서에 연결한다. 네이티브 앱 소스·집계·HealthKit 계산은 수정하지 않는다. 브라우저 검증은 카드 순서·보존·넓은 폭·큰 글씨·기존 진입과 비교안의 운동 선택 위치를 확인하며 실제 iOS/iPadOS 검증과 구분한다.

### 브라우저 한정 확인 결과

Flow 14개 폭/글씨/모드 배치에서 12개 카드의 순서·보존·가로 넘침 없음·월 목표 우선·세트 수/28일/최근 운동일 합계 표기를 확인했다. 기록 6개 상태와 기존 상세 5개 경로를 확인했다. 이 확인은 네이티브 실행이나 모든 데이터 상태의 합격 판정이 아니다.

402px·100%·밝음의 예시에서 추천 운동 시작 위치는 Compact 1667px → Flow 1244px, 개인 기록은 3258px → 2069px였다. 같은 브라우저 시안의 세로 배치 비교이며 실제 사용 시간·스크롤 횟수·iPhone 포인트를 측정한 값은 아니다. 변경된 라벨과 Flow의 새 시안 PNG를 보존했다.

2026-10-26 [최종 통합안](activity-final-proposal.md)에서 모든 피드백을 반영한 Flow 한 화면을 제시한다. 이 문서의 비교/조사 기록은 보존하며 최종 전용 시안은 별도 파일에서 연다.
