# Today 전체 상태·배치 계약

[방향 시안](../theme-map/themes/dune-today-restart.html) · [재설계 근거](today-restart-proposal.md). 실제 앱 캡처나 네이티브 검증 결과가 아닌, 현재 코드의 표시 조건을 확인해 만든 디자인 계약이다. 테마는 기존 **DUNE / Desert Warm**을 공통으로 유지한다. Compact·Metrics·Editorial은 배치 대안이며 새 테마가 아니다.

## 기존 전체 흐름과 제안

| 순서·내용 | 현재 코드 조건 | 시안의 밀도·표현 기준 |
|---|---|---|
| 상단 제목·알림·설정 | 전역, 알림함+새 소식 미확인 수, 최대 99+ | 큰 제목과 접힌 제목을 따로 비교. 모래 능선은 배경으로 유지하고 공간을 따로 예약하지 않음. 두 44pt 조작 영역 유지 |
| 컨디션 | 점수 존재. 없으면 미완성 기준선 | 점수·상태·짧은 설명. 큰 글씨에서는 점수를 별도 텍스트로 옮기고 링 장식 제거. 점수 0과 기록 없음을 구분 |
| 컨디션 추세 | 시간 표본 2개 이상 → 시간 추세, 아니면 서로 다른 날짜 2개 이상 → 주간, 아니면 부족 안내 | 기간과 단위 표시. 표본 1개는 추세 영역을 접고 짧은 안내로 대체. 없는 시간 구간을 선으로 연결하지 않음 |
| 제한된 기록 안내 | `hasLimitedConditionHistory` | 별도 큰 카드가 아닌 한 줄 상태. 점수나 데이터 누락의 이유를 인접하게 표시 |
| 어제 요약 | 06:00–11:59, 어제 점수 또는 수면 존재 | 수면·활동·걸음을 간단한 값 묶음으로. 10–11시에도 유지 |
| 오늘의 진행 | 22:00–05:59 제외 | 현재 코드는 **걸음+수면**이며 운동 시간/습관으로 바꾸지 않음. 목표 10,000보/8시간. 달성률 숫자는 100% 초과 허용, 막대만 100%에서 끝남. 오늘 표본 없음은 `—` |
| 오늘의 브리프 | 06:00–16:59, 브리핑 허용 또는 날씨/코칭 데이터 | 날씨·코칭·브리핑 진입을 한 카드로. 위치 없음과 날씨 조회 오류를 기록 없음으로 확대하지 않음. 날씨 없어도 건강 기록은 유지 |
| 회복·수면 | 유효 수면, 유효 부채, 수면 인사이트 중 하나라도 존재 | 수면 시간·**수면 날짜**·부채를 가까이. 표본 2개 이상일 때만 짧은 주간 그래프. 단일 값에 빈 차트 자리 없음. 부채 계산 불충분은 0 대신 `—` |
| 장기 스트레스 | 계산된 점수 존재 | **점수+수준+기간+상세**를 한 행에. 분석 근거는 인접한 44pt 펼침. 추가 링과 독립된 큰 CTA 영역 제거. 근거 누락은 계산에서 제외 |
| 운동 제안 | 06:00–16:59, 제안 존재, 휴식일 아님 | 부위·이유·컨디션/수면 근거 보존. 휴식일에는 카드 자체 제거. 계산할 수 없는 점수나 오래된 점수로 준비도를 단정하지 않음 |
| 인사이트 | 비수면 인사이트 최대 3개 + 선택적 루틴 제안 | 제목·내용·닫기를 가까이. 루틴의 Walking/3회/평균 14분/저장을 보존. 닫은 행의 공간도 함께 제거 |
| 오늘의 요약 | 17:00–05:59, 요약 존재 | 날짜·컨디션·걸음 요약, 원문 펼침. 브리프와 시간대 역할 구분 |
| 빠른 기록 | 일반 콘텐츠 하단 | 체중 기록·수면 진입 유지. 수면 없으면 Wellness로 연결하는 실제 목적지 계약 유지 |
| 고정 지표 | 선택한 지표의 유효 카드 존재 | 2열 요약, 마지막 하나는 가로 폭을 활용. 편집 가능. **고정 지표는 하단 그룹에서 제외**하는 현재 동작 유지 |
| 업데이트·일부 오류 | 업데이트 시각·부분 조회 오류 존재 | 측정일과 동기화 시각을 구분. 데이터 옆 개별 날짜와 전체 업데이트 시각을 함께 유지. 일부 오류는 기존 기록 위에 작은 재시도 안내 |
| 컨디션 지표 | 고정되지 않은 HRV/RHR | 값·단위·변화량·측정일. 유효 추세가 없으면 빈 점선 대신 단일 기록 안내 |
| 활동 지표·운동 기록 | 고정되지 않은 걸음/운동, 조회된 운동 | 지표는 작은 카드. 개별 운동은 이름·날짜·거리/시간을 가진 행. 최근 2개를 우선하고 나머지 5개는 펼침으로 보존. 운동명을 자르지 않음 |
| 신체 지표 | 고정되지 않은 체중/BMI/수면 | 3일 전 체중 73.9kg와 9일 전 BMI 25.2처럼 오래된 표본의 날짜를 명시. 차트가 없다고 빈 그래프 높이를 예약하지 않음 |
| 건강 Q&A | 진입은 항상, 지원 여부로 설명 변경 | 지원 기기는 수면·회복·운동 질문 진입. 미지원은 Apple Intelligence 지원 조건을 안내하고 기존 지표 상세 접근을 유지 |
| 탭 바·마지막 행 | native 탭 바 | 실제 구현은 safe area 내 마지막 행까지 스크롤 가능해야 함. HTML 시안은 전체 내용을 확인하기 위해 하단 자연 흐름으로 배치하며 native overlay의 실행 증거가 아님 |

## 전역 데이터 상태

| 상태 | 표시 | 금지·예외 |
|---|---|---|
| 첫 조회·런치 대기 | 짧은 skeleton과 로딩 설명 | 이전 데이터가 있는데 전체 skeleton으로 교체하지 않음 |
| 새로고침 | 기존 값 유지 + 작은 갱신 안내 | 값·섹션을 비웠다가 다시 채우는 점프 금지 |
| 기록 전혀 없음 | 한 번의 안내와 Activity 진입 | 가짜 0점·0시간·빈 카드 묶음 금지 |
| 건강 접근 필요 | 설정 진입과 이유 | HealthKit은 값이 없다는 사실만으로 사용자의 거부를 확정하지 않음. 실제 접근 실패 상태를 사용 |
| 일부 항목 없음 | 해당 지표/계산만 제외, 나머지 유지 | HRV 누락을 전체 데이터 실패로 취급하지 않음 |
| 전체 조회 오류 | 전체 오류와 재시도 | 기록 없음과 다른 문구·행동 |
| 일부 소스 오류 | 유효하거나 캐시된 값 + N/6 소스 실패 안내 | 캐시를 최신 측정으로 표시하지 않음 |
| 기준선 형성 중 | 모은 날짜와 준비 상태 | 0점을 실제 컨디션으로 표시하지 않음. 필요한 일수는 실제 `BaselineStatus` 사용 |
| 읽기 전용·클라우드 대기 | iPhone 동기화 대기 + 다시 확인 | 이 기기에서 HealthKit 측정을 요구하지 않음 |
| 단일 기록 | 값과 날짜, 짧은 추세 부족 안내 | 빈 점선/그래프를 위한 24–126pt 공간 금지 |
| 오래된 기록 | 개별 날짜 + 최근 컨디션이라는 문맥 | 어제·9일 전 값을 오늘 값으로 표기하지 않음. 오래된 운동도 마지막 기록에서 확인 가능 |
| 일부 날짜 누락 | 실제 표본만, 공백 구간 의미 유지 | 빈 날짜를 0으로 채우거나 연결된 관측처럼 생성하지 않음 |
| 유효한 0 | 0점/0걸음/0부채 등 관측값 의미 유지 | `0 == missing`으로 일괄 처리하지 않음 |

## 크기·접근성·문자열

- 폭: 320, 402, 첨부 Pro Max 기준 440, Duo 접힘 466, Duo 펼침 951, iPad 1032pt에서 **브라우저 배치**를 확인한다. 시뮬레이터의 실제 기기나 자세를 실행했다는 의미가 아니다.
- 글씨: 100/160/200%를 비교한다. 원문을 줄이거나 `minimumScaleFactor`로 숨기는 대신 행/열 전환. 네이티브 Dynamic Type의 모든 크기는 구현 이후 별도 확인한다.
- 기본 본문 정보는 14pt 수준, 값은 28pt, 보조 날짜·축은 11–12pt로 구별한다. 링·그래프·패딩·코너는 글씨 비율에 맞춰 함께 커지지 않는다. 이 수치는 이번 제안이며 HIG 의무값을 뜻하지 않는다.
- 작은 폭·큰 글씨: 지표 한 열, 스트레스 상세는 다음 줄, 운동 값은 이름 아래로. 버튼의 제목과 숫자는 자연 줄바꿈. 긴 한국어/영어/일본어를 모두 확인한다.
- 큰 폭: 본문에서 의미 있는 2열 구성, 지표 최대 3열. 왼쪽 내용만 길어졌다고 오른쪽 카드 전체 높이를 강제로 늘리지 않는다. 큰 글씨에서는 열 수를 줄인다.
- 대비 높이기: 테마를 바꾸지 않고 보조 텍스트·경계 대비를 강화한다. 의미를 색으로만 전달하지 않는다.
- Reduce Motion: OS 설정에서 광택 전환을 정지한다. 차트 값·점수·진행률은 장식 애니메이션으로 지속 변화하지 않는다.
- VoiceOver/키보드: 점수+의미+기간, 지표 값+단위+날짜를 읽는 순서. 닫기·고정 체크박스·펼침은 별도 이름과 실제 상태를 제공한다. 브라우저 구조 점검과 실제 VoiceOver 검증은 구분한다.

## 시안 안에서 확인할 동작

컨디션/스트레스/수면 상세, 스트레스 근거 펼침, 고정 편집과 원래 그룹 복귀, 인사이트/루틴 닫기, 이전 운동 펼침, 알림 모두 읽음, 브리핑/날씨, 템플릿 입력, 체중 입력 검증, 모든 데이터 진입을 로컬로 확인한다. 시안의 입력은 앱·HealthKit·SwiftData에 저장하지 않는다. 브라우저 목적지는 구성과 진입 확인용이며 해당 상세 화면 전체 개편이나 서버 연동 구현 완료를 뜻하지 않는다.

## 추가 화면에서 확인한 여백 원인

- `CumulativeStressCard.swift`: scaled 82pt 게이지+scaled 6pt 획, 24pt 내부 패딩, 각 20pt 간격, 별도 분석 행과 상세 행이 누적된다.
- `VitalCard.swift`: 유효 그래프가 없어도 24/28pt 점선 높이를 예약한다. 단일 운동·체중·BMI 카드에 반복되면 실제 정보보다 공간이 커진다.
- `DashboardView.swift`: 홀수 개 grid의 마지막 위치에 `Color.clear`가 들어간다. 카드가 하나인 그룹은 빈 반쪽이 생길 수 있다.
- `RecoverySleepCard.swift`: 그래프 높이가 기본 112pt에서 글씨와 함께 커진다. 설명과 부채 행까지 누적되어 기본/접근성 밀도 차이가 커진다.
- 날짜가 어제·3일 전·9일 전·22일 전으로 다른 표본을 같은 큰 카드처럼 다루면 현재 상태와 과거 운동 기록의 구별이 약해진다.

## 완료 수준

현재 범위는 전체 Today의 **디자인 시안과 상태 계약**이다. 실제 SwiftUI 구현·네이티브 스크롤/회전·VoiceOver·글씨 설정·safe area·시뮬레이터 캡처·앱 저장 연동은 이번 작업의 통과 항목으로 기록하지 않는다. 실제 앱 적용 시 해당 화면을 새로 캡처하고 실제 디자인맵을 갱신해야 한다. 브라우저 검사 결과는 별도 `today-restart-qa.json`에 보존한다.

## Compact 선택과 링 수정 (2026-10-26)

사용자는 Today에 Compact를 선택했다. Metrics·Editorial은 비교 자료이며 세 안의 하단 구성은 공통이다. Activity·Wellness·Life는 아직 개편하지 않았다. [구현 계획](../../plans/2026-10-26-today-compact-layout-and-ring.md)에 순서와 검증 기준을 확정했다.

시안 링은 외경104pt·획7pt·내부지름90pt로 고정하고 점수를 정중앙에 둔다. CONDITION은 같은 카드 상단에 유지한다. 86pt 축소를 제거하며 큰 글씨는 외부 점수로 전환한다. 0점에서는 진행 호를 숨긴다. 아이콘–숫자4–6pt, 링–설명12pt, 카드 패딩14–16pt를 기준으로 여백을 불필요하게 늘리지 않는다. 이 수정은 브라우저 시안에 반영했고 SwiftUI 적용은 아직 계획 단계다.
