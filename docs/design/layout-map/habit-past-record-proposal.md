# 지난 날짜 습관 기록 · L-P01 제안

사용자는 실천했지만 기록을 놓친 습관을 지난 날짜에 추가하는 경로를 요청했다. [Life 동작 시안](../theme-map/themes/dune-life-redesign.html)에 반영했다. L-P01은 시안용 화면 식별자이며 네이티브 화면 등록/구현 완료를 뜻하지 않는다. 기존 L05/L06 이력은 기록의 조회·수정을 잇는 목적지다.

> 2026-10-28 후속: 사용자가 실제 앱 구현과 PR 머지를 선택했다. [네이티브 계획](../../plans/2026-10-28-life-flow-native.md)에 따라 구현했으며 기기 검증을 진행 중이다. 아래 시안 작성 이력과 브라우저 PNG는 실제 앱 캡처가 아니다. 지난 기록 네이티브 화면 ID는 L09이며 시안의 L-P01과 구분한다.

## 진입과 배치

| 진입 | 동작 |
|---|---|
| L01 오늘의 실천 제목 오른쪽 `↶ 지난 기록` | 날짜 기록 폼. 기본 어제, 기본 습관은 물 마시기 또는 기록 가능한 첫 습관 |
| 습관 `••• → 지난 날짜 기록` | 그 습관이 선택된 폼 |
| 습관 이력 `＋ 지난 기록` | 선택 습관 유지. 날짜 행 `수정`은 그날 기존값으로 시작 |
| 실천의 리듬 상세 `＋ 지난 기록` | 날짜 기록 폼 |

화면 순서는 **습관 → 기록 날짜 → 그날 총값/완료 → 영향 한 줄 → 저장**이다. 체크는 완료 표시, 횟수는 단위 포함 총횟수, 시간은 총분을 입력한다. 이미 기록이 있으면 기존값과 `기록 수정`을 표시한다. 저장 뒤 선택 습관의 이력으로 가서 날짜·값·`나중에 기록`을 확인한다. 뒤로 가기는 Life로 돌아간다. 새 습관 생성은 기존 상단+를 유지하고 히어로에 이동/추가 버튼을 넣지 않는다.

## 기록 계약

- 실제 실천한 날은 `HabitLog.date`, 입력한 시점은 `completedAt`으로 구분한다. 기존 모델이 두 값을 지원한다.
- 기본 범위는 습관 시작일(시안은 생성일)부터 어제까지다. 오늘은 기존 조작, 미래는 일정 기능에서 다룬다. 실제 반복 시작 정책을 고려해 이른 날짜를 허용하는 별도 결정이 필요하면 이 계약을 명시적으로 갱신한다.
- 직접 기록한 습관만 선택한다. 자동 운동 연동/기본 도전을 수동으로 보충해 출처를 바꾸지 않는다.
- 한 날짜의 **총값**을 저장한다. 같은 날 기존3잔을8잔으로 고치면8잔이며11잔으로 합산하지 않는다. 중복 탭/동기화에도 같은 습관·날짜를 중복 완료로 세지 않는다.
- 저장 전 날짜·유효한 수·상한(분1–1440,횟수1–999)을 확인한다. 오류 시 기존값을 보존한다. 기록 삭제는 이 추가 경로의0입력으로 대체하지 않는다.
- 보통의 일간 습관은 과거 날짜의 이력/통계만 바꾸고 오늘 값을 완료시키지 않는다. 주간은 해당 주의 실제 완료일 수를 다시 계산한다.
- 반복 습관은 기록 날짜를 반영해 다음 예정일을 다시 계산하고 **저장 전에** 보여 준다. 시안은 화분을10.27에 완료로 기록하면 다음11.03으로 옮긴다. 오늘 완료 수를 올리는 대신 오늘 대상에서 빠질 수 있다.
- 이미 더 최근 완료가 있으면 그 최신 기준을 보존한다. 오래된 입력이 최신 예정일을 과거로 되돌리지 않아야 한다. 건너뜀·미룸·같은 날의 기존 행동이 있으면 전체 주기 이벤트를 기존 엔진으로 재평가한다. skip/snooze를 조용히 삭제하고 완료로 바꾸지 않는다.
- 저장 취소는 기록·오늘 목록·예정·주간/일별 집계를 함께 복원한다. 알림도 실제 저장 후 새 일정으로 다시 예약한다. 시안은 로컬 상태만 바꾸며 알림을 전송하지 않는다.

## 현재 소스와 후속 구현

`LifeViewModel.createValidatedLog(for:value:date:)`와 `createCycleActionLog(...date:)`는 날짜 인자를 받는다. `HabitLog`는 날짜를 당일 시작으로 정규화하고 입력시각을 별도로 저장한다. 그러나 현재 이력 화면은 조회 전용이며 루트 값 수정은 오늘 로그를 대상으로 한다. 따라서 메서드가 있다는 것만으로 과거 입력이 앱에서 가능하다고 보고하지 않는다.

후속 구현은 `HabitPastRecordSheet` 또는 동등한 별도 폼, 선택 날짜별 기존 로그 조회/총합 변경, 날짜·원천 검증, 검증 후 원자적 저장, 날짜별/주간 집계와 주기/알림 갱신이 필요하다. 기존 `todayLogs(for:date:)` helper는 재사용 가능성을 확인하되 오늘 전용 삭제 순서를 그대로 복제하지 않는다. 이력 inspector가 현재 저장값을 다시 읽도록 연결한다. en/ko/ja 문구와 L01/L05/L06 및 제안 폼의 영향 기기 캡처는 앱 구현 때 수행한다.

## 상태와 검증

등록 전/오늘/미래 날짜, 기존 부분기록·완료기록, 같은 날짜 재저장, 숫자 범위 초과, 체크/횟수/시간, 주간 날짜 중복, 반복의 이전/이후 완료·미룸, 자동/생성일이 오늘인 습관, 취소를 다룬다. 조회 중/일부 오류·오래된 동기화 데이터는 실제 DTO 상태로 구분해야 한다.

시안은 최소44px 조작과320/402/1032px·기본/200%·밝음/어두움의 폼을 검사한다. 네이티브 날짜 선택기·VoiceOver·CloudKit 경쟁/원자성·알림 복구는 브라우저 검사로 입증하지 않는다. 최신 결과는 [Life QA](../theme-map/themes/assets/life-redesign-qa.json)와 [통합 계획](../../plans/2026-10-28-life-tab-redesign.md)에 기록한다.
