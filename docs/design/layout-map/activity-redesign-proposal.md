# Activity 개편 시안

[Flow·Compact·Training 시안](../theme-map/themes/dune-activity-redesign.html) · [편집 원본](../theme-map/themes/assets/activity-redesign-fragment.html) · [Today Compact 기준](today-restart-proposal.md)

사용자가 Today 개편 진행사항을 참고해 Activity의 시안부터 요청했다. 이번 범위는 **A01의 방향 제안**이다. 수치·운동·날짜·근육 상태는 예시이며 실제 앱 캡처나 건강 기록이 아니다. SwiftUI 소스·카탈로그·현재 앱의 배치와 다른 탭은 변경하지 않는다. 세 방향 중 어느 것도 승인 또는 구현 완료로 취급하지 않는다.

## Today에서 이어받는 기준

- 사용자 선택인 Compact와 기존 DUNE 브라운·골드·모래 능선을 따른다. Today에서 폐기한 올리브·청록 새 팔레트를 재도입하지 않는다. 녹색은 근육 회복의 의미를 가진 작은 표시로만 쓴다.
- Today 전용 104pt 외경·7pt 획 링의 기하를 Activity 시안에도 제안한다. 중앙에는 점수만, `READINESS`는 카드 상단에 둔다. 실제 Activity의 공용 124pt 링은 아직 변경하지 않는다.
- 카드 내부 15pt, 카드 간 12pt, 링–설명 12pt를 제안한다. 이는 시안 값이며 Apple의 필수 규격을 뜻하지 않는다.
- 글씨가 커져도 패딩·원·플롯 높이를 비례 확대하지 않는다. 시안 130%부터 링을 숨기고 외부 점수·한 열 지표로 전환한다. 본문은 자연 높이를 사용하고 축소하지 않는다. 실제 Dynamic Type 전환점은 네이티브 구현 때 확인한다.
- 낮은 플롯·중첩 카드 축소·단위/날짜 인접 배치를 사용한다. 없는 표본에 빈 그래프 자리나 가짜 0을 만들지 않는다.

## 비교 방향

| 방향 | 위계 | 차이와 검토점 |
|---|---|---|
| Flow | 준비도 → 근육/부담 → 추천 → 최근 운동 → 기록/달성 → 통계/보고서 → 꾸준함/부하/구성 | Astra 자문·공식 자료 조사 후 추가한 최신 추천. 모든 카드를 보존하며 운동 선택과 성취를 앞당긴다. |
| Compact | 준비도 → 근육 회복·주간 통계 → 부담 요인 → 추천 운동 → 훈련 부하 → 보고서 → 최근 운동 → 개인 기록 → 달성 이력 → 페이스 → 운동 구성 | 현재 순서를 보존하며 조밀하게 다듬는 기본 제안. Today와 같은 인상을 유지하고 모든 섹션의 발견성을 보존한다. |
| Training | 준비도 → 근육 회복 → 부담 요인 → 추천 운동 → 최근 운동 → 주간 통계 → 훈련 분석 → 개인 기록 → 달성 이력 → 운동 페이스 | 운동을 선택하는 흐름을 앞당기는 대안. 준비도의 과거 변화와 하단 분석을 펼침으로 옮긴다. 달성 이력은 독립 카드로 보여 준다. 상세 발견성과 추가 조작의 대가를 함께 검토한다. |

초기 비교의 기본 추천은 Compact였으며, 전체 정보구조 자문 후 최신 추천은 Flow다. 준비도와 근육 회복을 확인한 뒤 현재처럼 주간 상태를 살펴볼 수 있다. Training은 운동 선택까지의 거리를 더 줄이고 싶을 때의 비교안이다. 바뀌는 것은 정보의 위치와 처음 펼쳐진 범위다.

## 현재 코드와 데이터 계약

확인한 기준은 `ActivityView.swift`, `WeeklyStatsGrid.swift`, `TrainingVolumeSummaryCard.swift`, `SuggestedWorkoutSection.swift`다.

| 항목 | 시안 계약 |
|---|---|
| 준비도 | 실제 앱의 준비도 점수·상태·요약을 사용한다. 그래프는 저장된 일별 준비도이고 마지막 값은 헤더 점수와 같아야 한다. 구성 근거는 HRV ms/수면 시간이 아닌 100점 기준 점수다. |
| 근육 지도 | 기존 앞·뒤 개략도 보존본을 재사용한다. 회복/볼륨과 제목 헤더의 부위별 상세 진입을 유지한다. 사용자 후속 요청으로 3D 버튼과 해당 시안 분기를 제거했다. 시안 색은 예시다. 부위별 실제 값·대상 수를 임의 산정하지 않는다. |
| 이번 주 | 훈련 볼륨 kg·소모 칼로리 kcal·운동 시간 분·활동일의 네 값을 유지한다. 변화는 현재 제공되는 비교값에만 붙인다. 시안은 10.20–10.26 최근 7일을 명시한다. |
| 부담 요인 | 부상 기록 충돌 배너는 해당 상태에만 표시하는 기존 계약을 유지한다. 상시 요약은 훈련량·간격·회복 설명이며 의료 진단으로 표현하지 않는다. 상세 목적지는 기존 injuryRisk다. |
| 추천 운동 | 검색 → 장소/장비 → 부위별 운동 → 추천 루틴/내 템플릿 → AI 운동 만들기 → 전체 운동. 긴 운동명은 줄바꿈하며 전체 화면 가로 스크롤을 만들지 않는다. |
| 추가 | 현재 상단 +는 운동 선택기를 연다. 시안에서도 같은 의미를 유지하며 근육 지도·준비도 카드에 중복 시작 버튼을 더하지 않는다. |
| 훈련 부하 | 최근 28일 부하와 마지막 운동 시간·칼로리다. 주간 근력 볼륨 kg와 같은 측정량으로 합치지 않는다. 예시 부하 그래프의 수치는 단위를 새로 정의하지 않는다. |
| 보고서 | 운동 횟수·활동일·볼륨·기간 비교·주요 근육군·하이라이트를 보존한다. 상세 시안은 진입과 요약 확인용이며 전체 기존 상세 화면의 재설계가 아니다. |
| 최근 운동 | 개별 세션의 날짜·시간 또는 거리·출처를 붙인다. Today의 종목별 집계와 구분한다. 처음 두 행, 이전 기록 펼침을 제안한다. |
| 개인 기록/달성 | 개인 기록은 종목별 최고 값·단위·날짜·출처를, 달성 이력은 시간순 이벤트의 종류·제목·내용·날짜·보상 포인트를 표시한다. 달성 이력은 최신 3개 예시를 보여 주며 현재 `AchievementHistoryPreview`의 기본 compact 개수와 맞춘다. 두 진입 모두 기존 개인 기록 상세를 사용하고 달성 이력 진입 시 해당 월별 이력 구역을 시안에서 보여 준다. 별도의 앱 목적지를 추가하지 않는다. |
| 페이스/구성 | 현재·최고 연속일과 월간 목표를 구분한다. 운동 구성은 최근 30일 운동 횟수 비율로 표시한다. 세트 환산 부위 비율과 혼용하지 않는다. |

## 상태와 동작

### 다른 워크트리의 상세 진입 기준 반영 (2026-10-26)

`codex/hrv-rhr-grouping` 워크트리의 채팅 **HRV 4와 RHR 타이틀 구획 정리**(thread `01a17847-e8f8-7922-bca2-2cc1b03e15c0`)에서 사용자가 승인한 기준을 확인했다. 적용 범위는 4개 메인 탭 전체이며 형태는 **제목 바로 옆 › + 헤더 전체 터치**다. 승인 대화와 확인 당시의 작업 중인 소스를 참조했으며 아직 완료/머지된 공통 컴포넌트로 취급하지 않는다. 후속 생성된 `docs/design/layout-map/card-detail-navigation.md`와 `docs/plans/2026-10-26-sleep-debt-and-card-navigation.md`까지 대조해 chevron 간격 4pt·독립 44pt 터치·중첩 버튼 금지·목적지 없는 헤더 숨김 규칙을 확인했다. 다른 워크트리는 수정하지 않았다.

- Activity 시안의 준비도·근육 회복·주간 통계·훈련 부담·부하·보고서·개인 기록·달성 이력·운동 페이스·운동 구성의 상세 진입을 같은 헤더 패턴으로 옮겼다. 화살표는 오른쪽 끝으로 보내지 않고 제목 뒤 4px 간격에 붙인다.
- 터치 영역은 헤더의 남은 전체 폭, 최소 높이 44px를 제안한다. 기본 focus 표시와 누르는 상태를 제공한다.
- 동일 목적지의 하단 ‘준비도 상세’, ‘달성 이력 보기’ 등 반복 링크는 제거한다. 검색·AI 만들기·운동 시작처럼 별도 행동은 해당 내용에 남긴다. 펼침 chevron은 펼침 동작으로 유지한다.
- 달성 이력은 두 방향 모두 독립된 `달성 이력 ›` 카드다. 시간순 최근 이벤트를 보여 주고 개인 기록의 최고 수치 카드와 구분한다. 새 예시 보상은 실제 사용자의 달성 데이터가 아니다.
- 준비도 구성은 처음에 항목별 구획으로 묶었고, 후속 사용자 요청으로 아래의 동일 척도 막대 그래프로 교체했다. 이름·막대·점수가 같은 행에 속하도록 구분 원칙을 이어간다. Today의 수면 부채 링은 Activity 데이터에 대응하지 않아 복사하지 않는다.

- 기본·일부 누락·첫 준비도 기록·기준선 형성 중·기록 없음·건강 접근 필요·처음 로딩의 7개 기록 조건을 전환한다.
- 일부 누락은 수면 구성 `—`, 중간 준비도 표본은 끊어진 선으로 표시한다. 0점은 유효한 관측값이며 호만 숨긴다. 100점은 완전한 원으로 표시한다.
- 첫 준비도 기록에서는 가짜 7일 곡선을 만들지 않는다. 기준선 형성 중에는 준비도 점수를 숨기지만 기존 운동 기록은 계속 보여 준다.
- 기록 없음에서는 주간 수치·개인 기록·회복 지도를 숨기고 기록 안내를 한 번 제공한다. 로딩과 접근 필요 상태는 기록 없음과 다른 문구를 쓴다. 상단 운동 진입은 남긴다.
- 휴식일은 추천 운동만 안내로 바꾸고 직접 운동을 선택하는 경로를 유지한다.
- 검색·장소·회복/볼륨·펼침·상단 +·상세 진입/복귀는 로컬 동작이다. 시작/AI 구성은 시안 확인만 하며 실제 운동·HealthKit·템플릿을 저장하지 않는다. 장비 화면은 배치 확인용이며 실제 추천 엔진의 장비 필터 검증이 아니다.
- iPhone 320/402/440pt, Duo 외부 466pt·내부 가로 951pt, iPad 1032pt를 폭 기준으로 비교한다. 폭 700px 이상에서 Compact의 근육/주간 통계는 두 열로 놓는다. 큰 글씨는 폭과 무관하게 한 열로 둔다.
- 넓은 폭의 하단 탭 바는 시안 탐색용이다. 실제 iPad·Duo 네이티브 탭 위치·방향·safe area 검증을 대신하지 않는다. Watch는 이번 범위에 없다.

## 검증

브라우저 시안의 결과는 [검사 기록](../theme-map/themes/assets/activity-redesign-qa.json)에 보존한다. 네이티브 빌드·UI 테스트·시뮬레이터 캡처는 이번 시안 범위에서 실행하지 않는다.

- 두 방향 × 6개 폭 × 4개 글씨 크기 × 밝음/어두움, 총 96개 조합에서 가로 넘침·링 기하·외부 점수 전환을 확인했다. 글씨는 100/125/160/200%이며 네이티브 Dynamic Type 검증이 아니다.
- 7개 기록 조건 × 두 방향의 14개 상태를 대조했다. 점수·기록 숨김, 단일 표본의 추세 제거, 상단 운동 진입을 확인했다.
- 회복/볼륨, 장소, 검색/빈 검색, 상단 운동 선택, 로컬 시작 확인, 휴식일, 준비도 0/1/71/99/100, Training 펼침 2종의 14개 검사를 통과했다. JavaScript 실행 오류는 없었다.
- 본문 끝 한 글자 줄바꿈과 장소 선택의 낱글자 줄바꿈을 보완했다. 밝음·어두움과 좁은 폭 큰 글씨를 육안 확인했다. 저장용 PNG는 고정 높이 iframe의 화면 밖 페인트가 누락돼 내부 문서 직접 렌더로 교체했으며 잘린 이미지는 삭제했다. HTML 시안·브라우저 PNG를 실제 앱 증거로 사용하지 않는다.
- 테마 맵 생성/동기화, 문서 상대 링크, 원본/보존본 해시와 `git diff --check`를 확인했다. DUNE 테마·한국어 범위이며 나머지 테마/번역과 실제 네이티브 탐색 위치는 미검증이다.

### 상세 헤더·달성 이력 후속 확인

현재 소스에서 두 방향×6개 폭×4개 글씨×밝음/어두움의 96개 배치 조합을 다시 확인했다. 제목–chevron 4px, 최소 44px 헤더, 달성 이력 최신 3건의 표시, 하단 중복 상세 제거를 검사한다. 각 방향의 준비도·근육·통계·부담·부하·보고서·개인 기록·달성 이력·페이스·구성의 헤더 오른쪽 빈 영역으로 이동/복귀하는 20건과 기록 부족 상태의 비활성 제목/상단 + 4건을 확인한다. 최초 시안의 검색·링·7개 상태 검사는 이전 소스 범위로 구분하며, 이번 결과는 헤더·달성 이력 변경에 집중한다.

### 개인 기록 강조·준비도 근거 막대 (2026-10-26)

사용자가 개인 기록의 달성감을 더하고 첨부한 준비도 구성 점수의 숫자 나열을 막대 그래프로 바꾸도록 요청했다. 이 후속 요청을 현재 시안에 우선 반영한다.

- 개인 기록은 기존 DUNE 표면 위 금빛 하이라이트·메달·`NEW BEST`로 강조한다. 종목명 → 기록 종류 → 최고 값/단위 → 이전 최고 대비 개선 → 날짜·출처를 표시한다. 레벨·배지 수·누적 포인트는 실제 `WorkoutRewardSummary`의 표시 항목에 맞춘 예시다. 반복 발광·축하 애니메이션은 추가하지 않는다.
- Squat 최고 중량 80kg/이전 75kg, Running 최고 페이스 5:14/km/이전 5:28/km를 예시로 사용한다. `ActivityPersonalRecord.previousValue`가 있을 때만 개선값을 표시하고, 페이스는 낮아진 시간이 개선이다. `NEW BEST`는 실제 `isRecent`가 참일 때만 표시하는 구현 계약이다. 5km 총 시간과 최고 페이스의 단위를 혼용하지 않는다. 이전 값이 없으면 임의 변화량을 만들지 않는다.
- 준비도 HRV64·수면83·회복72는 같은 0–100 척도의 가로 막대 세 행으로 비교한다. 각 행의 이름·실제 점수·100점 기준을 함께 표시한다. 막대는 목표 달성률 또는 합산 비중이 아니며 HRV ms나 수면 시간을 대신하지 않는다.
- 기본 막대 높이는 7px이며 글씨 확대와 함께 늘리지 않는다. 큰 글씨에서는 이름/값 아래의 전체 폭에 막대를 둔다. 수면 점수가 없을 때는 `—`와 기록 없음 접근성 이름을 쓰고 막대를 채우지 않는다. 유효한 0점과 기록 없음은 구분한다.
- 개인 기록 카드도 큰 글씨에서 한 열로 바꾸며 기록 숫자·단위·날짜를 축소하지 않는다. 제목 옆 4px chevron·헤더 전체 터치와 독립 달성 이력 카드는 유지한다.

최신 개인 기록/막대 보완 소스는 96개 배치 조합에서 넘침·막대 길이 64/83/72%·고정 7px 높이·두 개인 기록·헤더 4px/44px를 확인했다. 헤더 진입 등 24건에 수면 누락의 `—`/막대 없음 1건을 더해 25건이 통과했다. 밝음/어두움의 개인 기록 카드와 준비도 근거를 육안 확인하고 시안 PNG 17장을 갱신했다. 네이티브 앱 구현과 검증은 포함하지 않는다.

### 3D 진입 제거 (2026-10-26)

근육 범례 후속 확인: 두 방향×밝음/어두움×기본402px/큰 글씨320px×회복/볼륨의 16개 상태에서 범례 위치·10/5개 색상·지도 채움과 범례 색 일치·가로 넘침 없음·3D 제거 유지를 확인했다. 지도 카드 8장과 영향 상단/전체 화면 8장을 갱신했으며 그 밖의 카드 이미지는 유지한다.

### 훈련 부담 카드의 정보 보강 (2026-10-26)

사용자가 기존 안내 문장만 있는 카드의 정보 부족을 지적했다. `InjuryRiskAssessment`, `CalculateInjuryRiskUseCase`, `InjuryRiskCard`, `ActivityViewModel.recomputeInjuryRisk`의 실제 표시/입력을 확인한 뒤 제목 헤더 → 부담 수준 → 짧은 해석 → 기간 → 살펴본 기록 3개 → 기록 누락/확인 안내로 보강했다.

- 기본 예시는 `낮음`으로 표시하며 주간 훈련량 +12%/12,480kg, 연속 운동 1일/최근 10.25, 어깨·둔근 회복 진행을 제시한다. 기존 시안의 주간 통계·운동 페이스·근육 지도 예시와 의미를 맞춘다. 단순히 임의의 위험 점수를 더하지 않는다.

- 실제 앱 구현 시 상태는 `assessment.level`과 guideMessage에서, 부담을 높이는 근거는 `assessment.factors`에서 가져온다. 유효한 운동 통계/회복 맥락은 있을 때만 붙인다. 부상·수면·자세를 조회하지 못했다고 ‘이상 없음’으로 단정하지 않는다. 이번 HTML의 수준/행은 여전히 예시다.

- 기본 글씨는 한 행의 이름/근거와 오른쪽 값을 대응시키고, 큰 글씨에서는 값이 다음 행으로 내려간다. 각 행을 독립 카드로 중첩하지 않으며 제목의 chevron/전체 헤더 터치는 유지한다. 상세 시안에도 같은 관측값과 해석을 표시해 요약과 불일치하지 않게 한다.

훈련 부담 후속 확인: 두 방향×밝음/어두움×320/402/1032px 및 320px 큰 글씨의 16개 배치에서 세 관측값·기간·상태·44px 헤더·넘침 없음을 확인했다. 상세 진입/복귀와 수면/준비도 누락·전체 기록 없음의 12개 검사가 통과했다. 부담 카드 기본 4장·큰 글씨 1장·영향 전체 화면 4장을 갱신했다.

### 최근 운동의 배지·HealthKit·심박 (2026-10-26)

추가 요청은 운동 행 안에서 달성 배지와 HealthKit 연결, 평균 심박수를 함께 확인하는 것이다. `ExerciseListItem`·`UnifiedWorkoutRow`·`WorkoutBadgeView`·`WorkoutRewardEvent`의 현재 필드를 확인했다.

- 날짜·시간/거리·직접 기록 출처와 함께 평균 심박은 하트와 `평균 148 bpm`으로 표시한다. 값이 없으면 해당 표시만 숨긴다. 현재 `fromManualRecord`는 연결 여부와 무관하게 평균 심박을 전달하지 않으므로 수동 예시에 0 또는 임의 심박을 붙이지 않는다.

- 각 운동에 고유 ID를 부여해 이름이 같은 근력 운동 두 건도 서로 다른 날짜·값으로 상세가 열린다. 기본 최신 2개/이전 1개 펼침을 유지한다. 큰 글씨에서도 배지·출처·심박을 자연스럽게 줄바꿈하고 행 전체를 하나의 링크로 사용한다.

보고서/최근 운동 후속 확인: 두 방향×밝음/어두움×320px 기본/125%·402px 기본·320px 200%의 두 카드 총 32개 배치를 검사했다. 보고서 값·기간, 최근 운동의 5K/PR/보상 배지·연동 표시·실측 평균 심박(없는 수동 행은 미표시), 가로 넘침 없음과 8개 상세 진입이 통과했다. 최초 320px Training의 보고서 변화량이 3px 넘쳐 동일 높이 고정 대신 글씨 크기에 맞는 최소 폭과 자연 감싸기로 수정한 뒤 한 차례 재검증했다. 해당 카드 기본 8장·큰 글씨 2장·전체 화면 4장을 갱신했다.

### 전체 카드 배치 · Flow 추가 (2026-10-26)

사용자 요청으로 Astra에게 읽기 전용 자문을 받고 Gentler Streak·Hevy·Athlytic·Garmin의 공식 자료와 현재 집계를 확인했다. [정보구조 조사·카드별 결정](activity-information-architecture-study.md)에 근거와 데이터 의미를 보존한다. Flow는 준비도 → 근육/부담 → 추천 → 최근 운동 → 개인 기록 → 달성 → 주간 통계 → 보고서 → 꾸준함 → 부하 → 구성 순서다. 원래 두 배치도 비교용으로 유지한다.

현재 시안의 용어는 `운동 꾸준함`(연속일/월 목표), `근력 볼륨`(중량×횟수 kg), 근육의 `세트 수`, `훈련 부하`(28일 누적 흐름), `훈련 부담 점검`(평가)을 구분한다. 시간·칼로리는 코드상 최근 운동일의 합계여서 캡션을 `최근 운동일 ·10.25 합계`로 수정했다. 구성의 실제 계산 기간은 오늘 포함 28일이므로 과거 시안의 30일 표현을 정정한다. Flow의 꾸준함은 월 목표를 먼저 보여 준다. 통계/보고서는 출처 계약이 달라 아직 병합하지 않았다.

### 운동 구성 시각 강조 (2026-10-26)

사용자가 구성 카드의 시각적 강조를 요청했다. 근력/유산소는 덤벨/발자국 아이콘과 기본 42px의 68%/32%를 사용하고, 같은 금빛/녹색으로 구성 막대를 16px 높이로 표시한다. 막대의 두 채움 길이는 68:32이며 여백을 제외한 채움 비율을 유지한다. 범주 이름·정확한 수치·막대 접근성 설명을 함께 제공해 색에만 의존하지 않는다.

최근 28일·운동 횟수 기준은 그대로 유지하고 하체/등은 주요 근력 부위 태그로 구분한다. 부위 태그를 전체 운동 구성의 또 다른 비율로 표현하지 않는다. 새로운 운동 횟수·세트 수·이전 기간 변화는 만들지 않는다. 실제 앱에서 Other 기록이 있으면 해당 범주도 표시하고 수동/HealthKit 일부 조회 실패를 숨기지 않는 기존 계약을 따른다. 이번 수치는 근력/유산소 두 범주만 있는 시안 예시다. 큰 글씨는 두 범주의 수치를 세로 배치하고 막대 높이는 그대로 둔다. Flow의 위치와 제목 헤더 진입은 유지한다.

운동 구성 후속 확인: 세 방향×밝음/어두움×320px 기본/125%·402px 기본·320px 200%의 24개 배치에서 넘침 없음, 68:32 채움 길이, 16px 막대, 범주/막대 색 일치, 최근28일/운동 횟수 기준과 주요 부위 보존을 확인했다. 기존 상세 진입 6건이 통과했고 기본 카드 6장·큰 글씨 1장·영향 전체 화면 4장을 갱신했다.

2026-10-26 [최종 통합안](activity-final-proposal.md)에서 모든 피드백을 반영한 Flow 한 화면을 제시한다. 이 문서의 비교/조사 기록은 보존하며 최종 전용 시안은 별도 파일에서 연다.

### 운동명·계단 종목 표시 계약 · 2026-10-30

W26 운동 목록과 W28 HealthKit 상세, A01 최근 운동은 같은 일반 종목명 정규화 규칙을 사용한다. 기존 수정 제목 캐시의 `Running`·`Stair Climbing` 같은 정확한 일반 이름은 사용자 언어로 표시하고, `Bench Press`·`My Running Intervals` 같은 개별/사용자 제목은 유지한다. Strength/Dance처럼 같은 이전 이름을 공유하는 유형은 실제 활동 코드를 우선한다. 천국의 계단 기구(HK stairClimbing)와 실제 계단 오르기(HK stairs, 기존 내부 rawValue stairStepper)는 표시명으로 구분한다. 원래 코드·HealthKit 매핑·캐시 원문·사용자 수치는 변경하지 않는다. 목록 배치/터치 영역/테마는 유지한다. iPhone·iPad·Duo와 Watch의 일반 종목 레이블이 영향 대상이며 실제 캡처 완료 범위를 별도 기록한다.

이번 운동명 보완의 [새 실제 원본5장·82종 대응표·133개 운동 DB 검사·검증 및 미갱신 범위](../full-redesign-map/review/workout-name-audit-2026-10-30/index.html)를 통합 실제 화면맵에서 연결했다. 테마 방향과 배치는 변경하지 않았다.
