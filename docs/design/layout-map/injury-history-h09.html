H09 · 부상 이력

Wellness에서 들어가는 InjuryHistoryView의 목록 배치 계약입니다. DUNE 표현 시안은 설명용이며 앱 캡처가 아닙니다. H08 입력 Form, H10 상세, H11 통계는 각각 별도 화면입니다.

읽기와 행동 순서

  1. 시스템 제목 Injury History와 원래 통계 버튼
  2. Active 섹션: 각 기록의 원래 심각도 아이콘, 부위·측면, 심각도·기간, 날짜 범위, Active 상태
  3. Recovered 섹션: 같은 실제 기록 필드와 종료 날짜, Active 배지 없음
  4. 행을 누르면 H10 상세로 이동; 앞쪽 스와이프 또는 메뉴에서 Edit
  5. 활성 기록만 Recovered 행동; 뒤쪽 스와이프 또는 메뉴에서 Delete와 원래 확인 대화상자
  6. 기록이 하나도 없으면 원래 No Injury Records 빈 상태

보존 계약

데이터SwiftData의 날짜 내림차순과 실제 isActive 분류를 유지합니다. 부위·측면·심각도·기간·날짜는 저장된 기록만 표시하며 누락값이나 의료 위험 점수를 만들지 않습니다. 상태는 색만으로 구분하지 않습니다.
표현원래 InjurySeverity.iconName을 행 시작에 두고 큰 글씨와 함께 크기를 조정합니다. 밝은 화면에서는 원래 심각도색 아이콘을 더 진하게 표시하고 어두운 화면의 원래 색은 유지합니다. 부위 이름을 먼저 읽고 날짜 범위는 보조 글씨로 유지하되 지나치게 옅지 않게 합니다. Active·Recovered 섹션 머리말의 아이콘은 상태 이름을 대체하지 않습니다. 두 섹션 머리말의 글자와 아이콘은 DS.Color.textSecondary를 명시해 기본 시스템 머리말보다 읽기 쉽게 합니다.
기기·접근성일반 iPhone·iPad·Duo 접힘·펼침에 같은 행 필드와 행동을 둡니다. 접근성 큰 글씨에서는 기존 한 열 행으로 전환하고 부위·측면·기간·날짜·상태가 줄바꿈으로 모두 읽혀야 합니다. 통계, 행 상세, 편집·회복·삭제 행동의 도달성을 실제 PNG/AX에서 확인합니다.
근거이 HTML은 구현 전 기준입니다. 기존 네 H09 PNG는 화면 정체성 참고이며 현재 소스·UID·자세·AX에 결합된 전후 캡처가 아닙니다. 640cc681의 Duo 핵심 검사 3건과 실제 캡처는 이전 소스 기록으로 보존했습니다. 통계 전경 보정 후 현재 611d70b1의 네 프로필·다섯 사례·열 PNG/AX 쌍은 실제 검토 갤러리에 있습니다.

통계 버튼은 원래 chart.bar.xaxis와 동작·비활성 조건을 유지합니다. 실제 밝은 버튼 면에서 확인한 낮은 대비를 보완하도록 Light의 해당 버튼 tint만 진하게 섞고 Dark는 현재 테마 accent를 유지합니다. 수정 후 611d70b1의 밝은 화면 네 프로필을 실제 PNG/AX로 검토했습니다.

iPad 상세 이동 보존

각 기록 행의 첫 탭은 H10 상세로 이동해야 합니다. 행의 저장된 기록 ID를 화면 소유 선택 상태에 담고 현재 SwiftData 기록을 다시 찾아 상세를 엽니다. 기존 심각도 기호·상태·전체 행 터치 범위·화살표·스와이프·메뉴 행동과 시스템 뒤로 경로를 유지합니다. iPad에서 행 선택만 남고 상세가 열리지 않은 첫 실행 증거가 있으므로 수정 후 동일한 첫 탭을 실제 기기 프로필에서 다시 확인합니다.
