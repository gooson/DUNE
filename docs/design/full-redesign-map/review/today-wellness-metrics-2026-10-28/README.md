# Today 지표의 Wellness 통일과 행 높이

[새 실제 화면10장](index.html) · [개별 소스·기기·해시](manifest.json) · [실행 기록](proof/verification.json)

범주색 제목/아이콘·옅은 내부 면·큰 기본색 수치·실제 관측 추세·측정일로 Wellness의 읽기 계층을 맞췄다. `TodayMetricRow`가 각 열의 폭에서 자연 높이를 측정하고 행의 최대 높이를 각 셀에 제안한다. 전체 높이를 상수로 고정하지 않아 줄바꿈과 비교/추세 없음에도 같은 행의 표면과 내부 면이 정렬된다. 두 행 전체가 항상 같은 높이라는 뜻은 아니다.

HRV/RHR의 기존 캐시와 수면 분석의 실제 수면 시간만 사용한다. 최신 표시 기록일 이하·최근7일·유한한 양수의 관측을 시간순으로 정렬해 최대7개 전달한다. 2개 미만은 그래프를 생략하며 누락일을0으로 채우지 않는다. 체중/BMI 등 이 카드에 전달할 이력이 없는 항목은 가상 추세를 만들지 않는다. 비교가 없으면 기존 번역의 ‘No comparison record’를 표시한다. 추가 HealthKit 쿼리는 없다.

관련 UI5개 device-case와 새 단위2개를 확인했다. 최초 iPhone4개 중3개 통과·1개 실패는 큰 글씨 편집 목록의 체중 항목이 화면 밖에 있던 테스트 설정이다. 해당 목록을 스크롤하도록 보완한 뒤 실패한1개가 통과했다. 앱 코드3개는 최초 캡처 이후 바뀌지 않았고, 원본 patch와 base commit을 보존해 정상 상태·홀수·운동 행의 통과 증거를 재사용했다.

### 단위 실행의 제한과 대체 검증

표준 `scripts/test-unit.sh`의 전체 iOS 실행은 독립된 AI 건강 Q&A 평가의 medical safety1/3 실패를 기록했고, 다음 운동 템플릿 생성이 무출력300초 제한으로 종료됐다. UI/지표 코드와 해당 평가 서비스 사이의 변경 의존성은 없으며 AI 평가를 이번 작업에서 수정하지 않았다. 전체 단위 검사가 통과했다고 보고하지 않는다.

표준 실행기에 selector 옵션이 없어 임시 Xcode 테스트 계획을 시도했지만 suite/메서드 선택이0개로 처리됐다. 0개를 통과로 계산하지 않았고, 원래 scheme은 byte 단위로 복원했다. 실제 테스트 식별자를 Xcode의 읽기 전용 열거로 확인한 뒤 이미 빌드된 `metricTrendsUseObservedValues()`와 `singleObservationHasNoTrend()`만 `test-without-building`으로 실행해2개 통과를 확인했다. 같은 저장소 실행 잠금·전용 기기·소유 deadline을 유지했다. 표준 실행기 파일은 변경하지 않았다. 원본 실패/중단·0건 결과·최종2건 로그를 구분해 보존한다.

필수 iOS 빌드, 문자열 카탈로그 포맷, 테마 맵 동기화와 최종 diff 공백 검사를 별도로 확인했다. 새 번역 키·점수 계산·저장·테마 방향 시안은 바꾸지 않았다.

## Astra 검토

Astra는 원본 다크 두 장과 세 앱 소스를 읽기 전용으로 검토했다. P1/P2 없음. Wellness와 연결되는 범주색/면/큰 값과 수면·체중의 일치하는 위·아래 경계를 확인했다. 실제 관측 정렬·자료 부족 시 생략·별도 척도 문구도 일치했다. P3로 수면의 두 줄 값 때문에 체중 하단 여백이 커지는 점을 남겼다. 현재 잘림이나 의미 손실은 없고 자연 높이를 맞추는 범위에서 수용했다. Astra의 실제 검토 범위에 큰 글씨/iPad/VoiceOver는 포함하지 않았다.

## 미갱신 범위

T03 Duo 접힘·펼침, iPad 최대 글씨, 모든 언어/테마·기록 상태, 실제 VoiceOver와 전체 UI 회귀는 이번 미검증이다. 신고된 두 열 배치와 iPhone 큰 글씨에 검증을 한정했다. 해당 전용 기기/상태의 UI 실행과 새 캡처가 재개 조건이다. PNG는 카드/행을 중심으로 스크롤한 상태이며 상단·다른 섹션이 내비게이션 뒤에 있을 수 있다. 이전 Today PNG를 이번 변경의 새 증거로 바꾸지 않는다.
