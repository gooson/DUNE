# 오늘 밤 수면 카드 시각 개선

[새 실제 화면11장](index.html) · [이미지별 출처](manifest.json) · [검증 기록](proof/verification.json)

텍스트만 이어지던 예측을 큰 점수·달 상징·0–100 가로 게이지·신뢰도 배지·실제 팁 영역으로 구분했다. 수면색과 기존 카드 표면을 사용한다. 모델 점수와 low/medium/high를 그대로 시각화하며, 신뢰도 막대는 확률이나 건강 판정이 아니다. 측정하지 않은 수면 단계나 예측 추세는 만들지 않는다. 예측 카드의 상세 진입과 기록 펼침은 별도 동작이다.

| 기기·상태 | 관련 검사 | 새 원본 |
|---|---|---|
| iPhone · 37/low 다크, 78/medium·0/low·100/high 밝음 | 값·게이지의 AX 값·신뢰도·실제 기록 펼침/접힘 | 4장 |
| iPhone · 최대 글씨37/low·예측 없음 | 세로 배치·신뢰도·예측 없음의 게이지/배지 미표시 | 3장 |
| iPad · 37/low 다크, 78/medium·0/low·100/high 밝음 | 넓은 배치·값·신뢰도·기록 펼침/접힘 | 4장 |

수면/예측의 독립 상세 이동도 통과했다. 관련4개 device-case를 확인했다. 전체 UI 회귀와 공통 smoke를 이번 검사의 통과 범위로 확대하지 않는다. 예측 계산·기본 fixture의78/medium 값·실제 데이터 조회는 유지했다. UI 전용 점수/신뢰도/none 선택은 `--uitesting`과 기존 디자인맵 예측 flag에서만 동작한다.

최초 iPhone 실행은3개 중2개 통과·1개 실패다. 수면 일별 목록만 비우면 기존 실제 단계 요약의 fallback으로 예측이 생겨 빈 상태 fixture가 되지 않았다. UI 전용 `none`을 명시하도록 보완한 뒤 해당1개 재실행이 통과했다. 앱 컴포넌트와 값이 있는 fixture 동작은 바뀌지 않아 정상 상태/기록 펼침과 독립 상세 이동의 통과 결과를 재사용했다. 초기 소스는 base commit과 원본 patch의 gzip 보존본으로 기록했고 최신 커밋으로 바꿔 표기하지 않는다.

최대 글씨의 첫 캡처에서는 신뢰도 배지의 중간점이 hittable이어도 두 번째 줄이 탭바 뒤에 있었다. 추가 검사에서 단일 swipe의 관성으로 배지가 화면 위로 지나쳤고 AX y=-340.3을 확인했다. 해당 실패도 보존했다. 이동을 실제 배지 frame 기준의 최대220pt 드래그와 손 유지로 제한한 뒤 배지 전체 frame이 내비게이션 아래·탭바 위에 들어오는지 검사한다. 점수와 신뢰도는 긴 카드의 다른 스크롤 위치에서 촬영한다. 기본 밝음 중 일부도 스크롤로 상단이 가려져 있으며 전체 카드 증거로 확대하지 않는다. 대표37점 다크와 iPad에서 전체 구성을 확인한다.

필수 iOS 빌드와 UI test compile, 문자열 카탈로그 포맷·diff 공백·테마 맵 동기화 검사를 수행했다. 새 번역 키·저장 스키마·테마 방향 시안은 변경하지 않았다. 자동 UI 범위의 full fallback은 전체 회귀 요청이 없어 이 카드의 targeted 검사로 한정했다.

## Astra 검토

Astra가 읽기 전용으로37점 전체 카드와0/78/100 실제 PNG, 모델·컴포넌트를 검토했다. P1/P2 발견 없음. 큰 점수·달 패널·게이지가 시선을 잡고, 신뢰도와 팁의 영역 구분이 텍스트 중심의 휑한 느낌을 해결한다는 결론이다. 모델값과 시각 표현의 의미가 대응하며 상세 링크와 펼침은 분리되어 있다. Astra는 큰 글씨의 실제 배치나 VoiceOver를 확인한 것으로 보고하지 않았다. parent가 큰 글씨 캡처를 별도로 대조했다.

## 미갱신 범위

H01 Duo 접힘·펼침의 이 카드, iPad 최대 글씨·빈 상태, 모든 언어/테마, VoiceOver 순회와 실제 HealthKit 환경은 별도 미검증이다. 신고된 일반 iPhone 상태·접근성 크기와 iPad의 넓은 배치에 한정한 실행이다. 이 범위는 해당 전용 기기/상태를 실행해 새 캡처를 남겨야 갱신할 수 있다. 이전 Flow의 수면 예측 PNG는 이번 수정의 증거가 아니다.
