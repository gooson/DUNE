# CA02 장소 검색·선택 실제 화면

[새 원본 갤러리](index.html) · [출처·크기·SHA-256](capture-index.json) · [해결책](../../../../solutions/general/2026-10-29-cardio-place-search-selection.md)

opt-in 예시 이름·좌표를 사용하는 새 XCTest 캡처다. 실제 사용자 운동·현재 위치·시설 이용 증거가 아니다. 장소 선택 시 검색 키보드를 닫고 장소명·지도에 복귀하며, 하단 고정 `저장`으로 완료한다. 기존 PNG는 재사용하지 않았다.

## 검증 범위

| 기기 | 결과 |
|---|---|
| 전용 iPhone 18 Pro | 한글·초성 검색/선택/저장, 기존 장소 변경/취소 2건 통과. 신규 빈 장소의 긴 검색 목록 전체 경로 1건은 선택 전 테스트 조작 실패 |
| 전용 iPad Pro 13-inch (M5) | 한글·초성 검색/선택/저장 1/1 통과 |
| 전용 Duo 외부 | 한글·초성 검색/선택/저장 1/1 통과 |
| 전용 Duo 내부 | 빌드 후 테스트 기동 증거 없이 900초/124 종료. CA02 새 캡처 미완료 |

관련 검색 헬퍼의 Swift Testing 19개는 독립 macOS Swift Package에서 통과했다. 전체 iOS unit suite 또는 전체 UI 테스트 통과가 아니다. 컴파일·관련 UI만 검사했으며 실기기 GPS 정확도·MapKit 실서비스 결과의 완전성·HealthKit/CloudKit 동기화를 검증하지 않았다.

밝음·한국어·기본 글씨를 확인한다. 어두움·최대 글씨·다른 테마는 새 캡처 대상에 포함하지 않았다. Watch는 이 편집기를 사용하지 않아 영향이 없다. iPhone 캡처 후 초성 별칭 요청에서 미분류 시설을 허용하도록 네트워크 요청만 보완했고, 같은 fixture·렌더 경로의 증거를 재사용했다. iPad는 이 최종 코드로 새로 빌드·실행했다.

## 실패 이력과 남은 범위

- 초기 UI 2건은 `List.swipeUp`의 시작점이 키보드에 걸려 검색 결과까지 내려가지 못했다. 키보드·하단 버튼 위의 좌표로 보정한 뒤 기존 장소 변경/취소는 통과했다.
- 신규 빈 장소의 긴 목록은 keyboard AX frame의 시작 y=590pt보다 위에 있는 추천 영역에 시작 y=555pt가 걸렸다. 새 실제 PNG와 접근성 계층에서 목록이 그대로인 것을 확인했다. 제스처 여백을 100pt로 보완했지만 같은 원인 최대 1회 재시도 제한에 따라 해당 selector를 추가 실행하지 않았다. 신규 빈 장소에서 긴 목록 선택→다른 결과 재선택→동일 결과 재선택→저장/재열기 전체 경로는 미검증이다. 실패 화면은 갤러리에서 진단용으로 구분한다.
- 한글·초성 검색 UI와 기존 장소 변경/취소의 통과를 위 긴 경로의 통과로 확대하지 않는다. 향후 해당 테스트의 키보드 추천 영역 회피를 확인한 실행이 재개 조건이다.
- 한글 기능 추가 중 MapKit C 이름의 Swift 변환 차이 두 건을 발견해 `MKLocalPointsOfInterestRequest.maxRadius`, `MKLocalSearch(request:)`로 수정했다. 그 뒤 관련 단위 테스트와 iPad 앱 빌드·UI가 통과했다.
- Duo 준비 첫 실행은 보조 shell의 `ROOT_DIR` 누락으로 중단됐다. 경로 변수를 지정한 뒤 소유 등록 기기만 재사용해 부팅하고 외부 LCD 활성 readback을 확보했다. 사용자/다른 작업의 Duo를 종료하거나 초기화하지 않았다.

실행 receipt와 단위 결과 요약은 [evidence](evidence/)에 보존한다. 저장소의 현재 변경 내용은 별도로 남아 있으며 PR 생성·머지는 수행하지 않았다.

Duo는 소유 UDID `25D0A3A5-22BA-4DF8-A71E-BB9476ABAFEE`만 조작했다. 검토한 hinge source `7acb090dd7d28fb0aea8e1907211ceff15aa450e`와 현지 스크립트/C helper SHA-256 일치를 확인했다. 초기 Open 직후 조회는 외부 LCD 활성이었으므로 내부 캡처 완료로 보지 않았다. Device Hub에서 정확한 소유 기기를 선택해 slider 180을 확인한 뒤 공식 조회에서 LCD-1 활성·LCD 비활성을 확인했다. GUI 제어값을 센서에서 측정한 실제 각도로 표현하지 않으며 새 AX·원본 PNG와 별도로 대조한다.

## 최종 범위 · 2026-10-30

새 실제 원본은 11장(통과 사례 10장·실패 진단 1장)이며 iPhone·iPad·Duo 외부 상태다. 선택 이름·지도·하단 저장의 새 원본을 직접 확인했다. 관련 UI는 기기별 총 4건 통과, 신규 빈 장소 긴 목록 1건은 테스트 조작 실패 후 보정 미검증, Duo 내부 1건은 테스트 시작 증거 없이 900초/124 종료다. 내부의 기존 PNG는 사용하지 않았고 CA02 Duo 내부를 갱신 완료로 표시하지 않는다. 복구 후 재개 조건은 전용 Duo의 앱·AX·테스트 러너 기동 정상화 근거와 해당 selector의 새 실행이다. Mac 잠금 해제가 필요하다고 단정하지 않는다. [Duo 내부 실패 상태](evidence/duo-open-status.json)를 별도 보존한다.


2026-10-30 리뷰 후속: 기존 실패/재시도 이력은 보존한다. 새 native 단일 드래그 진단에서 추천 영역 밖의 y490→350 조작과 실제 목록 이동을 확인한 뒤, 원래 긴 목록 선택·재선택·저장/재열기 selector가 정상 종료·통과했다. 저장은 하단 하나로 정리했고 지역+시설 단어 카테고리 매칭도 보완했다. 최신 증거는 docs/design/full-redesign-map/review/cardio-atlas-polish-2026-10-30/를 따른다. 다른 기기의 기존 시작 장애를 복구 또는 통과로 바꾸지 않는다.
