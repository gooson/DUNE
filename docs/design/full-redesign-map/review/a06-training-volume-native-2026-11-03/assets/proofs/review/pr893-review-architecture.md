# A06 architecture review · 9adb50b8

## P2 · The weekly goal and previous-period comparison use different numbers of dates

The weekly goal reads the aggregate also used by the other three metrics, exercise types and comparison badges. The existing analyzer starts the current window at local midnight D−N and includes today through the reference time. It gives the previous window exactly N dates. A workout at D−7 and four workouts on distinct dates within D−6 through today can therefore complete the five-day goal a day early. For 1M the current summary includes 31 dates. The chart history already contains the intended 2N dates, starting at D−(2N−1). See `TrainingVolumeDetailView.swift:120–140`, `TrainingVolumeAnalysisService.swift:21–52` and `TrainingVolumeViewModel.swift:66–95`.

## P2 · HealthKit misses the first morning of the displayed previous period

The overview calls `fetchWorkouts(days: 2*N)`. The concrete query uses the current wall-clock time minus 2N calendar days as its lower bound and applies a strict start-date predicate. The analyzer starts at midnight on that earlier date and the manual snapshots cover it. For a noon load, a first-day 09:00 HealthKit workout is absent before analysis. The new previous-period card exposes the discrepancy for every total and delta. The analyzer also defaults to a second clock read after async fetch, which can move the summaries across midnight. See `WorkoutQueryService.swift:34–43`, `TrainingVolumeViewModel.swift:67–93`, and `TrainingVolumeDetailView.swift:233–252`.
