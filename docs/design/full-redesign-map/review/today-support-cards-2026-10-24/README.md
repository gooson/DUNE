# Today 보조 카드 수정 후 실제 화면

전용 iPhone18Pro B52BB289-B70B-46C6-9E57-C6C0D5D11D60에서 mock 자료로 실행한 실제 SwiftUI PNG다. 일반 밝음의 진행·회복, 어두움의 진행, 최대 글씨의 두 목표 타일 영역을 보존했다. HTML 시안·합성 이미지가 아니다. 소스7fe28b4c·56cab7da의 캡처이며 제품 코드는2c1380d4 이후 동일하다. 어두운 회복의 이전29e54f9a PNG는 최신 결과에서 제외했다.

## 검증 결과

- 최신 iOS 빌드 성공(56cab7da).
- 수면 관련 Swift Testing4개 실행4·통과4(2c1380d4). 이후 앱/단위 테스트 코드는 바뀌지 않았다. 처음의0개 실행은 통과로 인정하지 않았다.
- 공통 스모크+Today 첫 실행:32개 실행29개 통과3개 실패. 알림2개는 자동 브리핑 시트가 앞에 표시되어 실제 버튼을 누르지 못했다. 기준 코드에도 같은 자동 표시 로직이 있다. 기준 소스2개 비교 실행은 다른 작업의 공용 잠금 때문에 시작하지 못했다.
- Today 재검증:2개 실행1개 통과1개 실패. 최대 글씨는 통과했다. 밝음·어두움 검사에서는 카드 프레임 (16,257.667,370,533.333)의 아래 경계791pt가 실제 탭바 상단791pt에 맞았지만, 검사 도구가 임의로 뺀4pt 때문에 실패했다.
- 330dd2eb에서 검사 도구의 임의4pt 여유만 제거했다. 전체 카드가 실제 보이는 영역 안에 있어야 한다는 조건은 유지한다. 재실행 한도를 넘긴 추가 실행 승인 전에는 이 검사를 통과로 표시하지 않는다.
- PNG의 여백·정렬·단계 이름·Hours 단위·차트 위 눈금을 육안 확인했다. 실패한 전체 테스트를 통과로 보고하지 않는다.

## 남은 범위와 재개 조건

일반 iPhone의 최종 밝음·어두움 검사 재실행, iPad와 Duo 접힘·펼침 T03 새 캡처가 남았다. 새 Duo 전용 선택자는 실제 방향·짧은 높이를 검증하고 진행·브리핑·회복 상단·차트를 나눠 촬영한다. 아직 실행하지 않았다. Watch는 이 Today 화면의 소비자가 아니다. 전체 회귀는 실행하지 않았으며 선택 범위의 결과를 전체 통과로 확대하지 않는다.

최초 커밋 훅의 활성 로그 삭제 문제 이후 검증 로그는 .codex-checks에 보존했다. 공용 잠금과 새 기기 소유권을 확인한 뒤 해당 범위만 재개한다.
