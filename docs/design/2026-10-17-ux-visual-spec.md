# DUNE 출시 UX·비주얼 명세 v1

이 문서는 이번 대화에서 정한 **출시 화면의 목표 상태**다. 구현 완료를 뜻하지 않는다. [8개 테마 방향 시안](theme-map/index.html)은 표현의 기준이고, [실제 화면 디자인맵](phone-design-map/actual/index.html)은 현재 구현의 증거다. 시안의 수치·문구는 예시이며 실제 건강 데이터처럼 사용하지 않는다.

## 제품 경험의 중심

사용자가 앱을 열고 5초 안에 **지금의 상태 → 왜 그런지 → 다음에 할 수 있는 일**을 읽게 한다. 데이터는 결정의 근거, 테마는 그 결정에 집중하게 하는 분위기다. 모든 탭의 상단에 서로 다른 장면을 놓되, 점수·그래프·행동의 읽는 순서는 같다.

| 우선순위 | 화면에 보일 것 | 배치 원칙 |
|---|---|---|
| 1 | 상태·핵심 수치 | 첫 접힘 화면에서 읽힌다. 색만으로 상태를 표현하지 않는다. |
| 2 | 변화 그래프 | 히어로 안에서 실질적인 폭과 대비를 확보한다. 장식 능선과 시각적으로 구분한다. |
| 3 | 근거와 다음 행동 | 근거는 최대 2개, 주 행동은 1개다. 버튼의 문구와 목적지가 일치한다. |
| 4 | 탐색과 기록 | 보조 지표와 과거 기록은 아래 섹션 또는 상세 화면에 둔다. |

| 탭 · 실제 화면 | 첫 질문 | 첫 화면 정보 순서 | 상세로 내려갈 정보 |
|---|---|---|---|
| [Today T03](full-redesign-map/review/first-fold-ux-2026-10-22/iphone/T03-light.png) | 지금 컨디션은 어떤가? | 컨디션 히어로 안 상태 → 실제 변화 → 근거 2개 → 컨디션 상세 → 한 개의 시간대 요약 | 전체 지표, 반복 브리핑, Q&A, 과거 요약 |

| [Life L01](phone-design-map/actual/regular/images/L01.png) | 오늘의 습관에서 무엇이 남았나? | 오늘의 습관 → 다음 완료 가능한 항목 → 기록 완료 → 데이터가 충분할 때만 추세 | 월간 완료율, 90일 히트맵, 세부 습관 이력 |

### 탭별 구체적 화면 결정

**Today.** 상단 배경은 테마 장면이 가장 잘 보이는 곳이지만 제목·상단 컨트롤·히어로와 경쟁하지 않는다. 히어로 안의 시간별 그래프를 기본으로 유지하고, 시간별 표본이 부족하면 기간을 명시한 7일 그래프로 전환한다. 두 경우 모두 그래프 레이블과 기준선을 보여 준다. 값이 없으면 가짜 곡선을 만들지 않는다. 히어로 전체는 컨디션 상세로 이어지는 한 링크이며 하단에 목적지를 명시한다. 다른 루트 화면은 탭 바로 이동한다. Briefing·Digest·Insight가 동시에 있을 때는 현재 시간대와 관련성이 가장 높은 **한 블록**만 첫 화면에 놓는다.

**Activity.** 준비도 링 아래 빈 공간을 줄여 상태 문장, 운동 시작 경로, 근거 그래프를 한 시야에 둔다. 건강 데이터 조회가 길어져도 준비도 카드의 로딩 상태와 운동 검색·기록 경로를 먼저 표시한다. 실제 운동을 직접 시작할 수 없으면 CTA는 “추천 운동 보기”로 명명하고 추천 화면으로 이동한다. 2D 근육 지도는 이 탭의 강한 시각 자료로 남기되, 첫 행동보다 앞서거나 지나치게 큰 높이를 차지하지 않는다. 3D는 지도 상세의 보조 진입이다.

**Wellness.** 종합 점수와 “오늘 밤 수면” 예측 점수는 의미가 다른 값으로 명확히 구분한다. 히어로의 수면 막대는 날짜가 붙은 최근 기록과 유효한 7일 평균을 표기하고, 예측 카드는 미래 추정과 신뢰도를 담당한다. 같은 원인을 두 카드에서 반복해 강조하지 않는다. 신체 기록 버튼은 예측 카드 다음에 두며 기록이 없어도 입력 화면으로 열린다.

**Life.** 기록의 주인공은 완료율 그래프보다 **완료할 습관**이다. 현재 L01처럼 표본이 거의 없는 그래프가 화면 대부분을 차지하지 않게 한다. 완료율 차트는 해석 가능한 기간의 기록이 있을 때 표시하고, 그전에는 “기록이 쌓이면 추세가 보여요”와 오늘 할 일을 보여 준다. 완료 상태는 숫자·텍스트·표식으로 함께 전한다.

## 공통 히어로 계약

```text
화면 제목 · 필요한 상단 도구
테마 장면 / 능선
┌ 히어로 ──────────────────────────────────────┐
│ 상태 링 + 점수/상태 이름                       │
│ 현재 상태를 설명하는 짧은 문장                 │
│ 변화 그래프 + 기간 + 축/기준 설명              │
│ 근거 칩 최대 2개 · 같은 맥락의 상세 진입        │
└──────────────────────────────────────────────┘
[필요한 화면에서만 현재 탭의 기록 행동]
보조 섹션 · 기록 · 깊은 분석
```

- **링은 상태**, **그래프는 변화**, **능선은 테마**다. 그래프를 능선의 일부처럼 약화하거나, 링의 광택이 그래프 위를 지나가게 하지 않는다. 그래프는 선·면·점과 축 레이블을 함께 써서 실제 값과 시점을 읽을 수 있어야 한다.
- 링의 밝은 하이라이트는 현재 점수의 호를 따라 계속 흐를 수 있다. 점수·문자·그래프 위는 통과하지 않는다. 끝점 색은 테마 고유색을 갖되 건강 상태의 좋고 나쁨을 잘못 암시하지 않는다.
- 히어로 전체를 누르는 상세 링크 안에 별도 버튼을 중첩하지 않는다. Today 히어로는 컨디션 상세 목적지를 명시하고, 탭 전환을 주 행동처럼 강조하지 않는다. Activity의 운동 기록과 Wellness의 수면 상세처럼 목적지가 다른 실제 행동은 링크 밖에 둔다.
- 스크롤 이전 화면에서 상태·그래프·다음 행동의 관계가 드러나야 한다. 작은 기기와 큰 글씨에서는 가로 병렬을 세로로 바꾸며 내용을 숨기지 않는다.

## 시각 시스템

### 타입과 밀도

기존 `DS.Typography`와 `DS.Spacing`을 시작점으로 사용한다. 아래는 **DUNE의 목표 사용법**이며 Apple의 강제 수치가 아니다.

| 역할 | 목표 스타일 | 규칙 |
|---|---|---|
| 화면 제목 | 시스템 Large Title 또는 이에 상응하는 Dynamic Type 스타일 | 배경 위에서도 명확한 대비. 언어가 길면 잘림보다 줄바꿈. |
| 히어로 점수 | 둥근 계열 Bold, Dynamic Type 연동 | 숫자의 크기를 높이되 상태 이름이 사라지지 않는다. |
| 상태 문장 | `.body` 또는 `.headline` | 건강 상태를 과장하지 않고 1~2문장. |
| 그래프 값·근거 | `.subheadline` / `.body` | 보조 문구를 장식적인 초소형 활자로 만들지 않는다. |
| 메타데이터 | `.footnote` / `.caption` | 기간·단위·마지막 갱신처럼 부차적인 정보에 한정. 고정 9pt 레이블 제거. |

기본 본문은 시스템 Text Style의 스케일링을 따르고, 한국어·영어·일본어 및 가장 큰 접근성 글씨에서 카드 높이가 늘어나게 한다. 핵심 수치에 `.minimumScaleFactor`로 과도한 축소를 걸지 않는다. 실제 합성 화면에서 작은 일반 텍스트의 대비는 4.5:1, 큰/굵은 텍스트는 3:1 이상을 검증한다. iOS의 기본 텍스트 목표 17pt와 44×44pt 컨트롤 권장 크기는 [Apple 접근성 참조](https://developer.apple.com/design/human-interface-guidelines/accessibility/)에 따른다.

### 형태, 재질, 색

- 화면 배경은 테마의 넓은 색면과 능선을 담당한다. **가장 강한 곡선·광택·색 깊이는 히어로 하나**에 준다. 나머지 지표는 중간 카드, 이력은 작은 행으로 낮춘다.
- 현재 DS의 HeroCard 반경 20/24pt, StandardCard 12/16pt, InlineCard 8/12pt를 기본 계층으로 사용한다. 필요할 때만 토큰을 조정하고 테마마다 카드 모양을 새로 만들지 않는다.
- 카드 재질은 글자를 읽게 하는 배경이다. 밝은 테마의 연한 글씨와 어두운 테마의 발광 뒤 텍스트를 실제 렌더링으로 따로 측정한다. 색은 정보의 유일한 신호가 아니다.
- 건강 상태색, 경고색, 데이터 종류색은 테마 장식 팔레트와 분리한다. 예를 들어 FOREST라는 이유만으로 Today 점수를 녹색 “좋음”으로 해석하게 만들지 않는다. 상태 텍스트와 아이콘이 의미를 결정한다.
- 상단 도구·탭은 OS의 익숙한 동작을 유지한다. 장면 배경은 safe area 아래로 자연스럽게 이어지되, 탭·버튼의 경계와 터치 영역은 읽히게 한다.

## 테마 장면과 움직임

모든 테마는 **상단 배경 → 히어로 표면 → 링 → 그래프 강조 → 다른 탭의 배경**으로 이어지는 한 언어를 갖는다. 모든 화면을 똑같은 애니메이션으로 덮지 않는다. 탭을 옮겨도 같은 테마의 리듬은 유지한다. 주기와 진폭의 실제 값은 구현 화면 녹화에서 다듬는다.

| 테마 | 장면·지속 움직임 | 링·그래프의 역할 |
|---|---|---|
| [DUNE](theme-map/themes/dune-design-direction.html) | 모래 언덕의 먼 능선과 가까운 능선이 서로 다른 속도로 계속 흐른다. | 금빛 링의 호에 밝은 점이 순환. 그래프는 모래 능선과 별개인 선명한 데이터 선. |
| [OCEAN](theme-map/themes/ocean-cool-direction.html) | 일본 판화에서 착안한 굵고 밝은 포말과 겹친 해류가 교차한다. | 포말의 두께는 장면에만 적용. 그래프는 포말 속에 묻히지 않게 독립 대비. |
| [FOREST](theme-map/themes/forest-green-direction.html) | 안개와 숲 능선이 깊이 차이를 두고 이동한다. | 금빛 링과 읽기 쉬운 추세. 상태 의미를 녹색으로 고정하지 않는다. |
| [SAKURA](theme-map/themes/sakura-calm-direction.html) | 꽃 군집과 얇은 가지는 장면을 만들고, 적은 꽃잎만 느리게 움직인다. | 연한 배경 위의 글자와 그래프를 충분히 진하게 유지. |
| [ARCTIC](theme-map/themes/arctic-dawn-direction.html) | 고요한 배경에서 오로라 **빛 띠만** 천천히 이동한다. 바다는 필수 요소가 아니다. | 오로라가 카드 뒤를 지나가도 그래프와 글자는 흔들리지 않는다. |
| [SOLAR](theme-map/themes/solar-pop-direction.html) | 태양 코어는 고정, 주변 빛의 궤적만 맥동한다. | 발광은 링 가장자리에서만. 값의 변화처럼 오해될 반복 점멸을 피한다. |
| [CONTOUR](theme-map/themes/contour-atlas-direction.html) | 굵은 기준선과 등고선이 느리게 호흡한다. | 그래프는 등고선과 다른 선 굵기·색·축 설명을 사용. |
| [WATER LILIES](theme-map/themes/water-lilies-direction.html) | 푸른 수면, 겹친 초록 붓질, 많은 작은 보랏빛 꽃점. 수련 무리가 수면에서 좌우로 흔들린다. | 잎을 매끈한 원반으로 그리지 않는다. 회화적인 경계와 여러 군집을 유지. **현재는 시안 전용**이다. |

**모션 계약.** 루트 화면에서 배경 모티프의 움직임은 낮은 진폭으로 지속하고, 터치 가능한 컨트롤·본문·실데이터 그래프는 움직이지 않는다. 진입 시 링 채움은 한 번, 링 광택은 읽기를 방해하지 않는 수준으로 순환한다. 데이터 갱신은 값 변경으로만 알리고 장식의 반복을 알림처럼 쓰지 않는다. `Reduce Motion`에서는 장면과 링을 의미가 완전한 정지 상태로 표시한다. 배터리·성능이 제한된 상태에서도 데이터와 조작은 즉시 남아야 한다.

## 데이터 상태와 문구

| 상태 | 표시 | 주요 행동 |
|---|---|---|
| 권한 요청 전 | 왜 데이터가 필요한지, 어떤 값이 사용되는지 | 권한 설정으로 이동 |
| 권한 거부 | 현재 읽을 수 없는 지표를 명확히 표시 | 설정 열기 또는 수동 기록 |
| 권한은 있으나 기록 없음 | 점수와 그래프를 비우고 “아직 기록이 없어요” | 가능한 기록 시작 |
| 기준선 수집 중 | 필요한 기간과 남은 조건을 사실대로 설명 | 나중에 다시 보기 / 가능한 행동 |
| 유효한 값 있음 | 값·단위·비교 기간·마지막 갱신을 함께 표시 | 해당 상세 또는 추천 행동 |
| 오래된 값·동기화 지연 | 마지막 측정 시각과 불확실성을 명시 | 다시 확인 |
| 오류·오프라인 | 이전 값이 있으면 시각적으로 구분하고 새 값처럼 보이지 않게 함 | 재시도 또는 기록 열기 |

문구는 한국어 기준으로 차분하고 구체적으로 쓴다. 예: “HRV가 평소보다 낮아요. 오늘은 가벼운 운동을 고려해 보세요.” “완벽”, “반드시”, “위험 확정”처럼 건강 판단을 과장하는 말은 피한다. 수면 기록이 0분이면 “잘 쉬었어요”를 표시하지 않는다. 빈 상태와 그래프의 의미는 VoiceOver에서도 같은 순서로 읽히게 한다.

## 화면 크기·접근성·품질 기준

- **일반 iPhone:** 첫 접힘 화면에서 상태·변화·행동의 순서를 유지한다. 그래프가 화면 폭을 충분히 쓰며 아래 카드가 히어로를 덮지 않는다.
- **iPad / Duo 펼침:** 히어로를 무작정 늘리지 않는다. 좁은 읽기 열과 실제 그래프/행동의 보조 영역으로 나눈다. 데이터가 없다면 빈 오른쪽 절반을 만들지 않는다.
- **Duo 접힘 / 창 크기 변경:** 같은 내용이 한 열로 자연스럽게 바뀌고 버튼이 접힘 경계에 놓이지 않는다.
- **VoiceOver / Voice Control:** 링은 “점수·상태·기간”으로, 그래프는 “변화 방향·최소/최대·현재 값·기간”으로 설명한다. 그림만으로 의미를 전달하지 않는다. 각각의 버튼 이름은 실제 목적지를 말한다.
- **Dynamic Type / Bold Text / Increase Contrast / Reduce Motion:** 각 설정에서 잘림, 겹침, 저대비, 의미 손실이 없어야 한다. 밝음·어두움 및 한국어·영어·일본어를 함께 확인한다.
- **애니메이션 성능:** 스크롤·탭 전환·운동 기록 입력을 우선한다. 여러 장식 레이어가 동시에 갱신돼 프레임이 떨어지면 모티프 수나 샘플링을 낮춘다.

## 출시 구현 순서와 완료 판정

1. **상태와 행동 복구:** 무반응 버튼, 권한/기록 없음 혼동, 사실과 맞지 않는 문구를 해결한다.
2. **공통 히어로·Today:** 그래프를 강화하고 상태→근거→행동을 재배치한다. 기본 DUNE의 상단 능선·링 광택을 이 계약의 기준 구현으로 만든다.
3. **Activity·Wellness·Life:** 각 탭의 첫 질문에 맞게 정보 밀도를 줄인다. 기록·딥링크·알림 목적지는 유지한다.
4. **7개 기존 테마 전개:** 공통 컴포넌트에 각 테마의 장면과 모션을 적용한다. WATER LILIES는 후속 구현 결정이 있기 전까지 테마 맵 시안으로 보존한다.
5. **검증·보존:** 영향받은 화면·상태·기기를 실제로 새로 캡처해 [실제 화면 디자인맵 갱신 절차](phone-design-map/README.md#화면-수정-시-갱신)를 따른다. 테마 표현을 바꾸면 같은 작업에서 [테마 맵](theme-map/README.md#갱신-방법)도 갱신한다.

명세 이행은 **4탭 각각에서 사용자가 상태·변화·다음 행동을 이해하고 완료할 수 있음**, 데이터가 없는 상태에서 거짓 수치가 없음, 주요 CTA 무반응 0개, 접근성 설정에서 의미 손실 없음, 실제 화면 캡처와 시안 구분 유지로 판단한다. 출시 정책과 건강 데이터 동기화 심사는 별도 출시 검토 대상이며, 이 디자인 명세가 승인이나 해결을 대신하지 않는다.

## 보류 결정

- 4탭을 3탭으로 줄이거나 Life를 Wellness로 옮길지는 사용성 관찰 이후 판단한다. 현재 명세의 **4탭 유지**는 출시 화면의 기준이다.
- WATER LILIES의 수련 형태는 이번 시안을 보존하고 후속 시각 개선을 거쳐 앱 테마 채택 여부를 결정한다.
- 모션의 초 단위 주기, 빛의 세기, 그래프 높이는 실제 기기에서 본 뒤 최종 토큰으로 정한다. 이 문서의 시각적 역할과 행동 계약은 그 조정 중에도 유지한다.
